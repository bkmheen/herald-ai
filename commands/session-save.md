이번 세션에서 수행한 작업을 정리한 **개발기록 마크다운 파일**을 생성하십시오.
이 기록은 "어떤 작업이, 언제, 어떻게 진행되었는지"를 나중에 확인하는 용도입니다.

> 참고: 파일로 저장하지 않고 **시간별 작업 차례만 화면에 보고 싶으면** `/session-log` 를 사용하십시오.

## 0. 필터 범위 결정 (인계 우선순위)

저장 범위는 아래 우선순위로 정합니다.

1. **이 명령의 인자 `$ARGUMENTS` 가 있으면** → 그 조건을 사용 (직전 상태 파일을 덮어씀).
2. **인자가 비어 있고, 직전 `/session-log` 의 상태 파일이 있으면** → 그 필터·목록을 그대로 이어받음.
3. **둘 다 없으면** → 전체 작업 저장 (필터 없음).

상태 파일을 먼저 확인하십시오:

```bash
source ~/.claude/skills/task-tracker/scripts/instance-resolve.sh
# cwd 해시 키 — /session-log 과 동일 규칙으로 같은 디렉토리의 상태 파일만 읽는다(동시 세션 오염 방지)
CWD_HASH=$(printf '%s' "$PWD" | shasum -a 256 2>/dev/null | cut -c1-12)          # macOS·대다수 Linux
[ -z "$CWD_HASH" ] && CWD_HASH=$(printf '%s' "$PWD" | sha256sum 2>/dev/null | cut -c1-12)  # Linux(coreutils)
[ -z "$CWD_HASH" ] && CWD_HASH=$(printf '%s' "$PWD" | md5sum 2>/dev/null | cut -c1-12)      # Linux 폴백
[ -z "$CWD_HASH" ] && CWD_HASH=$(printf '%s' "$PWD" | md5 2>/dev/null | cut -c1-12)         # macOS 폴백
[ -z "$CWD_HASH" ] && CWD_HASH="default"
STATE="$RUNTIME_DIR/.session_log_state__${CWD_HASH}.json"
if [ -f "$STATE" ]; then echo "=== 인계 상태 파일 발견 ==="; cat "$STATE"; else echo "(상태 파일 없음 — 인자 또는 전체 기준으로 진행)"; fi
```

> 이 명령은 herald-ai 의 `task-tracker` 스킬(`instance-resolve.sh`)에만 의존합니다. 상태 파일이 없어도 대화 맥락으로 재구성해 정상 동작합니다.
>
> 검증: 읽은 상태 파일의 `cwd` 가 현재 `pwd` 와 다르면 인계를 신뢰하지 말고, 대화 맥락에서 이번 세션의 실제 작업을 재구성하십시오. (cwd 해시 분리로 일반적으로는 일치하지만, 안전 확인)

- 인자(`$ARGUMENTS`)가 주어진 경우: 상태 파일을 무시하고 `/session-log` 과 동일한 **카테고리 태그 규칙**(아래 표)으로 작업을 다시 추립니다.
- 인자가 없고 상태 파일이 있으면: `items` 를 그대로 사용하되, 누락된 세부는 대화 맥락으로 보강합니다.
- 인자가 없고 상태 파일도 없으면: 전체 작업을 수집합니다.

### 카테고리 태그 (인자로 직접 필터할 때 사용)

| 태그 | 범위 |
|------|------|
| `개발` | 기능 구현·코드 작성·리팩터링 |
| `버그` | 버그 수정·디버깅·원인 분석 |
| `테스트` | 테스트 작성·실행·검증(QA) |
| `문서` | 문서·주석·기록·README 작성 |
| `리서치` | 조사·분석·검토·비교 |
| `git` | 커밋·브랜치·머지·푸시·배포 |
| `설정` | 환경·설정·도구·의존성 구성 |
| `기타` | 위에 맞지 않는 작업 |

## 1. 먼저 수집 (상태 파일이 없거나 인자로 재필터할 때)

- **작업 디렉토리**(가장 중요): `pwd` 로 현재 절대경로를 구하고, git 저장소면 `git branch --show-current` 와 이번 세션 커밋(`git log --since=... --date=format:'%m-%d %H:%M' --pretty=format:'%cd | %s'`)으로 시각·내용을 보강하십시오. (상태 파일이 있으면 `cwd`/`git`/`period` 를 우선 사용)
- **세션 작업 내역**: 대화 전체를 되짚어 이번 세션에 실제로 한 일을 **일자·시간 순서**로 정리하십시오(커밋 시각을 앵커로). 추측 금지 — 실제 한 일만.

## 2. 빈 결과 처리

- 필터 적용 후 항목이 **0건**이면 **파일을 생성하지 말고**, "조건에 맞는 작업이 없어 저장하지 않았습니다 (조건: {…})"라고 보고한 뒤 종료하십시오.

## 3. 파일명·위치

- 위치: 환경변수 `HERALD_LOG_DIR` 가 설정돼 있으면 그 경로, 없으면 `~/Desktop/`.
  (셸에서 `echo "${HERALD_LOG_DIR:-$HOME/Desktop}"` 로 대상 디렉토리를 먼저 확인하십시오. 없으면 생성.)
- 파일명: `{YYMMDD}-{요일} [{작업디렉토리 basename}{·필터범위}]-{HHMM} 세션 작업기록.md`
  - `[{작업디렉토리 basename}]` 부제목이 어느 프로젝트의 기록인지 식별합니다 — 예: `herald-ai` → `[herald-ai]`.
  - **필터가 적용된 경우** basename 뒤에 `·{범위}` 를 덧붙여 구분한다 — 예 include={개발}, exclude={테스트} → `[herald-ai·개발]`. 필터가 없으면 범위 접미는 생략한다.
  - `{HHMM}` 은 종료(생성) 시각. **여러 날에 걸치면 종료일 `{끝MMDD}`** 로 대신 표기(예: 06-13~06-14 → `-0614`).
  - 예(2026-06-13~14, herald-ai, 개발만): `260613-토 [herald-ai·개발]-0614 세션 작업기록.md`
  - 같은 이름 재생성 시 ` (2)` 등으로 덮어쓰기 회피.

## 4. 문서 구조 (반드시 이 순서)

```
# {제목} — 세션 작업기록

> **작업 디렉토리**: `{절대경로}`        ← 맨 앞·가장 중요
> **브랜치 / 저장소**: {git 정보(있으면)}
> **일시**: {시작 일시} ~ {끝 일시}
> **필터**: {인자/인계 조건 원문 → 포함 {태그…} / 제외 {태그…}, 또는 "없음(전체)"}
> **버전/커밋**: {버전 변화·커밋 수(있으면)}

## 요약 (개괄)
- 시간대별 개괄. 예: `20:11~22:00 — 1. A 작업 · 2. B 작업 · 3. C 작업`
- 몇 시부터 몇 시까지 무엇을 했는지 한눈에. (번호 매김 1./2./3. 권장)

## 작업 목록 (일자·시간별)
1. ({MM-DD HH:MM}) [{태그}] {작업명}
2. ({MM-DD HH:MM}) [{태그}] {작업명}
   … (시간 순)

## 세부 내용
### 1. {작업명}
- 배경/증상/목적 → 조치 → 검증/결과(테스트·커밋 해시 등)
### 2. {작업명}
…
```

## 5. 작성 원칙

- **작업 디렉토리**와 **요약**을 반드시 맨 앞에. 작업 디렉토리는 이 기록이 어느 프로젝트의 것인지 식별하는 핵심 정보.
- **필터가 적용되면** 제외된 범위는 기록에 넣지 않되, `> **필터**` 줄에 어떤 범위만 담았는지 명시한다.
- 요약은 개괄식(시간대 + 무엇을). 세부는 항목별로 "무엇을 왜 어떻게 + 검증/커밋". 상태 파일의 `detail` 을 세부 작성의 출발점으로 활용.
- 사실만. 커밋이 있으면 해시·버전을 함께. 미해결·후속 과제도 명시.

## 6. 마무리

- 파일을 쓴 뒤, **저장된 절대경로**와 한 줄 요약(적용 필터 범위 포함)을 보고하십시오.
- 인계에 사용한 상태 파일은 보고 후 정리해도 됩니다: `rm -f "$STATE"` (다음 세션 혼선 방지). 단, 같은 범위로 재저장할 여지가 있으면 남겨 둡니다.
- 추가 요청(특정 섹션 강조, 형식 변경 등)이 있으면 이 명령에 덧붙여 반영하십시오.
