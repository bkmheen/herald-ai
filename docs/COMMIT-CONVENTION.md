# 커밋·버전 규약 v3.1.0

> **한 줄 요약**: `patch = 묶음 × 10 + 커밋(1자리)`. 묶음 상한 없음.
> **읽는 법은 언제나 같다 — 맨 뒤 한 자리가 커밋, 그 앞이 전부 묶음이다.**

이 문서는 여러 저장소에서 **공통으로 쓰는** 커밋·버전 규약의 정본입니다.
herald-ai 저장소에 두는 이유는 하나입니다 — **clone 하는 모든 맥에 같은 규약이 따라가야** 하기 때문입니다.
머신 로컬 메모리에 적으면 그 맥에서만 살고, 새 맥은 규약 없이 시작합니다.

- 규약 버전 **v3.1.0** · 작성 2026-08-16 · 이전판 v2.0.0
- **호출어**: 사용자가 **"v3.1 커밋 체계"** 라고 하면 이 문서를 적용합니다 (아래 「호출됐을 때 할 일」).
- 정본 우선순위: 글로벌 `~/.claude/CLAUDE.md` §0·§3 → 프로젝트 `CLAUDE.md` → 세션 합의
- v3.0.0 에서 바뀐 것은 **버전 규칙 하나**이고 나머지 장은 v2.0.0 그대로 유효합니다.

## 호출됐을 때 할 일

사용자가 "v3.1 커밋 체계로 (해라 / 맞춰라 / 커밋해라)" 라고 하면:

1. **현재 버전을 읽는다** — `VERSION` 파일 · `pubspec.yaml` · 직전 커밋 제목 순으로 확인.
2. **다음 번호를 계산한다** — 커밋 자리 +1. **커밋이 9 였다면 다음 묶음의 `x0`** 으로 넘어간다.
   묶음 넘기기 판정은 아래 표를 따른다.
3. **granularity 를 점검한다** — 이질적인 변경이 섞여 있으면 커밋을 나눈다 (한 커밋 = 하나의 논리 변경).
4. **동반 기록을 갱신한다** — `CHANGELOG.md` · `DEVLOG.md` · 버전 파일. `x0` 커밋이면 묶음 머리말도.
5. **검증을 돌리고 결과를 기록한다** — 그 저장소의 검증 명령(`flutter analyze`·`npm run lint`·`pytest`·`bash -n` 등).
6. **HEREDOC 으로 커밋한다** — 제목 형식·본문 순서·트레일러는 아래 그대로.
7. **push 는 별도 요청이 있을 때만** 한다.

규약을 적용할 수 없는 상황(예: 이 저장소는 다른 번호 체계를 쓴다)이면 **커밋하기 전에 알린다.**

## 1. 버전 규칙

```
major . minor . patch          patch = 묶음 × 10 + 커밋
                                      └ 1~ (상한 없음) ┘ └ 0~9 ┘

  1.5.10   = 묶음 1   · 커밋 0        (새 체계의 첫 번호)
  1.5.247  = 묶음 24  · 커밋 7
  1.5.1230 = 묶음 123 · 커밋 0
  1.5.10000 = 묶음 1000 · 커밋 0      (자리가 늘 뿐, 읽는 법은 같다)
```

| 자리 | 부르는 말 | 올리는 주체 |
|---|---|---|
| `major` | — | **사용자 지시** |
| `minor` | — | **사용자 허락** (Claude 는 근거를 들어 요청만 한다) |
| 일의 자리를 뺀 나머지 | **묶음** | Claude 자체 판단 |
| 일의 자리 | **커밋**(subpatch) | **커밋마다 +1** |

- 묶음의 첫 커밋은 **`x0`** (묶음 2 시작 = `20`)
- **커밋 9 도달 → 자리 침범 방지를 위해 강제로 다음 묶음**
- **묶음 상한 없음** — 999 를 넘으면 patch 가 한 자리 길어질 뿐이다
- **minor 가 오르면 patch 는 항상 `10` 에서 시작한다.** `x.y.0` 은 쓰지 않는다 —
  `x.y.0~x.y.9` 는 "묶음 0" 이라 정의되지 않는 구간이다
- **zero-padding 금지** (semver 가 leading zero 를 금지한다). 문서에도 `묶음 24` 로 적는다
- 버전은 **단조 증가**한다. 지나온 값으로 되돌아가지 않는다
- **규칙을 또 바꾸면 minor 를 올려 경계를 만든다** — 같은 minor 안에서 patch 의 뜻이 바뀌면
  과거 번호를 해석할 수 없다

### 묶음은 주제가 아니라 10커밋 구간이다

**주제를 잇는 것은 마일스톤 태그와 `DEVLOG.md`** 다. 한 주제가 묶음 여러 개에 걸치는 것은 정상이다.

| | 판정 |
|---|---|
| **강제 전환** | 커밋이 9 에 도달 |
| **선택 전환** | 새 기능·화면 착수 · 성격이 다른 영역으로 전환 · 신규 외부 API 연동 · 인프라/빌드 변경 · 사용자 지시 |
| **전환하지 않음** | 같은 주제의 후속 수정 · 문구/간격/색 조정 · 직전 작업의 버그 수정 · 문서 갱신 |

> 개정 근거(2026-08-16 실측): 종전 "묶음 = 작업 주제" 로 세어 보니 한 묶음이 13·14·7 커밋이었다.
> 1자리로 줄이면 쪼개지지만, 커밋 2자리는 거의 쓰이지 않고 묶음은 **하루 4개**씩 생겨
> 2자리(99) 상한이면 25일이면 소진된다. 주제 추적은 태그가 이미 더 정확하다.
> 종전 목표 "묶음 10~40 커밋" 은 폐기됐다.

### 소급 재번호 금지

이미 push 된 히스토리를 다시 쓰는 것은 **위험 대비 실익이 없다.** 소급 트레일러도 넣지 않는다.
과거 커밋의 모델명·작성자도 고치지 않는다 — 당시 작업한 주체의 기록이기 때문이다.

### 빌드 번호 `+N`

App Store `CFBundleVersion` / Play Store `versionCode` 식별자다.

- **유지가 기본** — 일반 커밋에서 건드리지 않는다 (`1.5.10+1` → `1.5.11+1`)
- **Claude 자체 판단 증가 금지** — 사용자 명시 요청, 또는 필요성을 인지했다면 **묻고 승인받은 뒤에만**

## 2. 커밋 승인·범위

- **자체 판단 커밋 금지.** 사용자 명시 요청 시에만.
- **세션 시작 디렉토리가 속한 저장소에만** 커밋한다. 다른 저장소는 사전 확인.
- `git -C <세션시작경로>` 로 대상 저장소를 명시한다.
- 예외: 사용자 지시 / 도구가 규정상 쓰는 임시·런타임 경로.

## 3. 커밋 granularity

**한 커밋 = 하나의 논리 변경.**

| | |
|---|---|
| 분리 기준 | 문서 ↔ 코드 · 플랫폼별(iOS/macOS/웹/Android) · 빌드 산물 · 기능 추가 ↔ 의존성 제거 |
| 허용 묶음 | 짧은 CHANGELOG entry + 버전 파일 patch 증가 |

## 4. 커밋 메시지 형식

```
v<버전> [<slug>] <한국어 요약>

<본문 — 원인 → 조치 → 검증 순>

<트레일러>
```

- **제목**: 버전 접두 필수 · 한국어 · `[slug]` 는 세부 작업 구분 라벨
  - slug 예: `[ui]` `[docs]` `[auth]` `[build]` `[server]` `[convention]` `[env]` `[privacy]` `[install]`
- **본문**: **원인 → 조치 → 검증** 순서
- **작성 방법**: HEREDOC — `git commit -F - << 'EOF'` (셸 확장·따옴표 사고 방지)

### 트레일러

| 항목 | 내용 | 어디에 |
|---|---|---|
| `Co-Authored-By` | `Claude <모델명> <noreply@anthropic.com>` — **그 커밋을 실제로 작성한 모델의 이름** | 모든 저장소 |
| `Worked-On` | 세션 호스트명·IP·작업 디렉토리 | **비공개 저장소만** |
| `Committed-To` | 원격 커밋 시만. 같은 호스트면 생략 | **비공개 저장소만** |
| `Model` | 예: `claude-opus-5[1m]` | 비공개 저장소 (공개 저장소는 `Co-Authored-By` 의 모델명으로 갈음) |

> ⛔ **공개 저장소에서는 `Worked-On`·`Committed-To` 를 쓰지 않는다.** 호스트 이름과 IP 가
> 커밋 메시지에 영구히 남는다. 공개 저장소의 트레일러는 **`Co-Authored-By` 한 줄만** 둔다.
>
> **작성자 신원** — 커밋 작성자·커밋터 이메일은 공개해도 되는 주소여야 한다. 머신 기본값
> (`<계정>@<호스트>.local`)이 그대로 들어가면 계정명과 호스트가 공개된다.
> clone 뒤 `git config user.email <공개 주소>` 로 고정한다.

## 5. 커밋 동반 필수 작업

1. **`CHANGELOG.md`** — Keep a Changelog 형식 (`Added` / `Changed` / `Fixed` / `Removed` / `Verified`)
2. **버전 파일** — `VERSION` · `pubspec.yaml` 등. 버전 증가, **빌드 번호는 유지**
3. **`DEVLOG.md`** — 작업 배경·의사결정·TODO 갱신
4. **검증** — 그 저장소의 검증 명령을 돌리고 결과를 `Verified` 에 기록한다.
   검증하지 않은 것을 "완료" 라고 적지 않는다

### 마일스톤·묶음 기록

- `x0` 커밋의 CHANGELOG 머리말: `> **묶음 N — <제목>** (slug: <slug>)`
- `DEVLOG.md` 상단 "현재 묶음" 줄 갱신
- **주제가 끝날 때 태그**: `git tag -a milestone/<slug> -m "<설명> (1.5.10~1.5.34)"`
  묶음 경계가 아니라 **주제 경계**에 붙인다. 한 태그가 묶음 여러 개를 아우를 수 있다

## 6. 금지 · 재확인

| | 항목 |
|---|---|
| **사용자 요청 없이 금지** | `git commit --amend` · `--no-verify` · `--no-gpg-sign` · pre-commit 실패 시 `--amend` 덮어쓰기(→ **새 커밋**을 만든다) |
| **재확인 필수** | `git push --force` · main force push · `reset --hard` · `branch -D` · `clean -f` · `checkout .` · `rm -rf` · DB drop/truncate · 외부 메시지 발송 · 운영 인프라·CI/CD 변경 · 패키지 다운그레이드 |

In-progress 상태(uncommitted · untracked · stash · lock 파일)를 발견하면 **임의로 정리하지 않는다.**
조사한 뒤 사용자에게 묻는다.

## 7. push

- **사용자 명시 요청 시에만.** 자동 push 금지.
- **언급 전 `git remote -v` 로 가능 여부를 먼저 확인한다.** 리모트가 없는 저장소에서
  "push 는 지시하시면 진행합니다" 류의 말을 꺼내지 않는다.
- `--force` · main force push 는 추가 재확인.
- 브랜치를 push 하면 **앞선 미푸시 커밋이 함께 올라간다.** 그런 경우 무엇이 함께 올라갔는지 보고한다.

## 8. 이력 구간별 해석

번호를 거슬러 읽을 때 필요한 표다. **소급 재번호를 하지 않으므로 구간마다 규칙이 다르다.**

| 구간 | patch 의 뜻 | 예 |
|---|---|---|
| `1.3` 이하 | 커밋 일련번호 | `1.3.95` = 95번째 커밋 |
| `1.4` | 묶음(2자리) × 100 + 커밋(2자리) | `1.4.203` = 묶음 02 · 커밋 03 |
| **`1.5` 이상** | **묶음 × 10 + 커밋(1자리), 상한 없음** | `1.5.247` = 묶음 24 · 커밋 7 |

> 저장소마다 도입 시점이 다르다. **herald-ai 는 2026-08-16 에 전 이력을 1회 소급 재번호**해
> 최초 커밋부터 이 체계로 통일했고(그때가 체계 도입 시점의 예외였다), 이후로는 소급하지 않는다.
> 자세한 것은 [`CLAUDE.md`](../CLAUDE.md) 「버전 관리 규칙」.

## 저장소별 적용 범위

**어느 저장소가 이 규약을 쓰는지는 이 공개 저장소에 적지 않습니다.** 저장소 이름·서버 호스트·
경로는 개인 구성이므로, 각 맥의 로컬 메모리와 비공개 볼트에 둡니다
([`CLAUDE.md`](../CLAUDE.md) 「공개 저장소 원칙」 — *도구는 공개, 구성은 비공개*).

저장소마다 제목 형식이 다를 수 있습니다(예: 앱 저장소는 `v1.5.247 [ui] …`, 서버 저장소는
`[0.54.6] …`, 모듈 저장소는 `## [0.30.10] <모듈> - …`). **커밋 전에 그 저장소의 직전 커밋
제목을 확인해 형식을 맞춥니다.** 버전 계산 규칙(§1)은 형식과 무관하게 동일합니다.
