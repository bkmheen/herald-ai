# herald-vault 설계 — 왜 이런 구조인가

여러 컴퓨터에서 일하며 남는 **세션 기록·기억·환경 스냅샷을 한 저장소로 모으고,
필요할 때 가장 먼저 그곳을 뒤져 찾게** 하는 것이 목적이다.

이 문서는 **왜 그렇게 만들었는가**만 담는다. 설치·운영 절차는 [`VAULT-SETUP.md`](VAULT-SETUP.md),
기록 형식은 [`SESSION-RECORD.md`](SESSION-RECORD.md) 를 본다.

> **도구는 공개, 구성은 비공개.** herald-ai(이 저장소)는 누구나 쓰는 도구이고,
> 어떤 서버·어떤 주소·어떤 호스트를 쓰는지는 **각자의 `~/.herald/vault.conf` 와
> 자기 vault** 에 있다. 이 저장소에는 그런 값이 들어가지 않는다.

---

## 1. 두 저장소로 나눈다

| | 무엇 | 왜 |
|---|---|---|
| **herald-ai** (공개) | 스크립트·스킬·슬래시 커맨드·설계 문서 | 여러 컴퓨터에 `git pull` 로 퍼뜨려야 한다 |
| **herald-vault** (비공개) | 세션기록·기억·인계·환경·호스트 대장 | 서버 주소·고객 정보·보안 진단이 들어간다 |

한 번 섞이면 되돌릴 수 없다. 그래서 **처음부터 저장소를 가른다.**

원문(대화 `*.jsonl`)은 용량이 커서(수백 MB) 본문 저장소의 이력을 무겁게 만든다.
Git LFS 를 쓰는 **별도 저장소**(`herald-vault-raw`)로 분리한다.

---

## 2. 권한 — 쓰기는 보편, 읽기는 등급

요구는 "모든 컴퓨터가 자기 기록을 남길 수 있어야 하되, 남의 기록을 읽는 것은 통제한다" 였다.

**핵심 제약: git 호스팅에는 「쓰기 전용」 권한이 없다.** 쓰기 권한은 읽기를 포함한다.
저장소를 호스트별로 쪼개도 "자기 기록조차 읽지 못한다"는 요구는 달성되지 않는다.

→ **git 권한이 아니라 별도의 투입 통로로 푼다.**

```
┌─ 일반 호스트 ──────────────────────┐
│ 기록 생성 → 로컬 대장과 대조         │
│ 안 보낸 것만 tar + 압축             │
│        │ SSH forced-command         │  ← 넣기만 가능
│        ▼ (restrict: 셸·scp·sftp 차단)│
│ 실패 시 outbox 큐에 적재             │
└─────────────────────────────────────┘
              ▼
   vault 서버 : inbox/<host>/
              ▼
┌─ 관리 호스트 ───────────────────────┐
│ 회수 → 제자리 정리 → 색인 → push     │
└─────────────────────────────────────┘
```

| 항목 | 결정 |
|---|---|
| 통로 | SSH + `command="…herald-drop <host>",restrict` |
| 수신 프로그램 | 표준입력을 파일로 쓰는 것만 한다. **파일을 내보내는 코드 경로가 없다** |
| 호스트 식별 | **서버가 키에 박아 둔 값.** 클라이언트가 위조할 수 없다 |
| 회수 | `authorized_keys` 에서 그 줄 하나를 지우면 즉시 차단 |

`rsync` 를 쓰지 않은 이유 — 동기화 도구라 양방향이 기본이다. 한쪽으로만 흐르게 하려면
인자 필터링을 신뢰해야 하는데, "내보내는 코드가 아예 없다" 는 편이 확실하다.

## 3. 전송은 로컬 대장 기반 파일 증분

| 항목 | 결정 | 근거 |
|---|---|---|
| 증분 단위 | **파일 단위** | 세션 원문의 99.2%가 종료 후 불변이라 바이트 델타의 이득이 0.8%뿐이다 |
| 판단 근거 | **클라이언트의 로컬 대장** (경로 → sha256·크기) | **서버에 묻지 않는다** — 물으면 그것이 곧 읽기 통로가 된다 |
| 진행 중 세션 | 보내지 않는다. 종료 후 1회 | 각 파일이 평생 한 번만 전송된다 |
| 대장 분실 | 전량 재전송하되 서버가 해시로 중복 제거 | 낭비는 대역폭 1회분뿐 |

바이트 델타를 쓰지 않은 이유는 이득이 작아서만이 아니다. 델타는 **원본을 영구 보관해야 하는
의존**을 만든다. 꾸러미끼리 의존하지 않는 편이 복구를 단순하게 만든다.

## 4. 세 계통을 나눈다

한쪽이 고장 나도 나머지가 계속 돌도록 **대장·꾸러미·수신함·수집기·저장소를 계통별로 나눈다.**

| | **docs — 문서** | **raw — 원문** | **env — 환경** |
|---|---|---|---|
| 내용 | 세션기록·기억·인계 | 대화 원문 `*.jsonl` | 호스트·도구 상태 스냅샷 |
| 대장 | `sent-docs.json` | `sent-raw.json` | (매번 전량 — 작다) |
| 저장소 | 본문 | 원문(LFS) | 본문 |
| 하루 용량 | 수십 KB | 수십 MB | 수 KB |

## 5. 정체성 — 이름도 주소도 정체성이 못 된다

컴퓨터 이름은 여러 개고(ComputerName·LocalHostName·hostname), IP 는 네트워크마다 바뀐다.
그래서 **변하지 않는 하드웨어 식별자를 1차 키로 쓴다.**

| 플랫폼 | 식별자 |
|---|---|
| macOS | `IOPlatformUUID` |
| Linux | `/etc/machine-id` |
| 못 얻으면 | 랜덤 UUID 를 발급해 `~/.herald/machine_id` 에 캐시 |

**이름·주소는 "속성" 으로 이력만 남긴다.**

```yaml
# vault conventions/hosts.yaml
- machine_id: <불변 식별자>
  names: [{name: <이름>, since: <날짜>}]
  addrs: [{ip: <주소>, since: <날짜>, net: home}]
  tier_read: all
```

→ 이름이나 IP 가 바뀌어도 **같은 컴퓨터로 이어진다.**

**기기를 교체해 `machine_id` 자체가 바뀌면** 사람이 알려 주어야 한다. 도구가 추정하지 않는다 —
사용자가 선언하면 그때 과거와 미래가 한 호스트로 묶인다.

```bash
herald-host alias <옛 machine_id> <새 machine_id> --since <날짜> --note "기기 교체"
```

**프로젝트 정체성은 작업 디렉토리 basename** 이다. 호스트마다 경로가 달라도 basename 이 같으면
같은 작업으로 묶인다. 이름을 바꿨다면 별칭을 등록해 잇는다 —
**등록하지 않으면 별개로 남는다.** 명시되지 않은 동일성을 추정하지 않는다.

## 6. 색인은 파생물이다

`/session-save` 는 **기록 파일 하나만** 쓴다. 통합 타임라인(`INDEX.md`)과 기계용 색인
(`index.json`)은 `herald-index` 가 전체를 훑어 **매번 새로 만든다.**

저장할 때 타임라인에 한 줄씩 덧붙이는 방식은 폐기했다 —
**일반 호스트는 vault 를 읽지 못하므로 타임라인을 갱신할 수 없다.**

색인이 파생물이면 레거시 이관·회수·수동 편집 어느 쪽이 끼어들어도
**한 번 다시 돌리면 정합이 회복된다.** 정렬을 UTC 로 고정했으므로 어디서 돌려도 결과가 같다.

---

## 7. 이 설계가 지키는 것

- **사실을 지어내지 않는다** — 모르는 호스트는 `unknown`, 추정 항목은 `inferred`,
  시각을 모르면 날짜만 보여 준다
- **멱등** — 색인·정리·이관 모두 몇 번 돌려도 결과가 같다
- **되돌릴 수 있다** — 파일 이동은 전부 매니페스트로 추적한다
- **판본이 드러난다** — 모든 기록이 `schema:` 로 자기 규약 판본을 밝힌다
- **경계를 흉내내지 않는다** — 읽기 차단은 규약이 아니라 서버가 판정한다
