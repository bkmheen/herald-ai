# ha-we — 작업환경(work_env) 체계

> **한 줄 요약**: `ha-we-<id>` 는 "작업 디렉토리 한 벌" 이다. 각자 버전을 가지며,
> 이름만 부르면 **최신 버전**이 펼쳐진다.

- 체계 버전 1.0.0 · 작성 2026-09-18
- **호출어**: 사용자가 **"ha-we"** 또는 **"ha-we-<id>"** 라고 하면 이 문서를 적용한다.
- 약칭: `ha` = herald-ai · `we` = work_env

---

## 1. 무엇인가 (그리고 무엇이 아닌가)

`ha-we` 는 **작업 디렉토리를 통째로 배포**하는 체계다. 코드 저장소 템플릿이 아니다.

풀려는 문제는 하나다 — **Claude Code 의 대화 기록도, 홈의 기억 폴더도 컴퓨터 간에 동기화되지
않는다.** 그래서 같은 프로젝트를 다른 맥에서 이어 열면 맥락이 통째로 사라진다.
`ha-we` 가 뿌리는 디렉토리는 **이어받는 방법을 자기 안에 들고 있다.**

| 구성 | 푸는 문제 |
|------|-----------|
| `CLAUDE.md` 세션 시작 절차 | 어느 맥에서 열어도 "무엇부터 읽어야 하는가" 가 디렉토리 안에 있다 |
| `.claude/hooks/sync-memory.sh` | 기억을 프로젝트 사본과 양방향 동기화. 슬러그를 경로에서 계산하므로 어느 맥·경로든 대응 |
| 진행 기록 디렉토리 | 서술형 이력 — 무슨 일이 있었고 **왜** 그렇게 정했나 |
| 산출물 디렉토리 | 산출물 이력 — 같은 물건의 버전을 갈아 끼운다 |

## 2. 이름 규칙

```
ha - we - <id>
│    │     └ 개별 작업환경. 소문자·숫자·밑줄. 예: work_ppt
│    └ 필드 이름 (work_env)
└ herald-ai 약칭
```

- **`id` 는 "무엇을 만드는 작업인가" 로 짓는다.** `work_ppt` = 발표자료 만들기.
- **산출물 종류가 다르면 다른 환경이다.** 보고서를 만든다면 `work_ppt` 에 인자를 더하는 것이
  아니라 `work_doc` 을 새로 만든다. id 가 모양을 정하고, 버전이 개선을 담는다.

## 3. 버전 규칙

각 환경은 **자기 버전**을 가진다.

```
0.1  →  0.2  →  0.3  →  …        기본: minor 만 +1
```

| 자리 | 올리는 주체 |
|------|-------------|
| major | **사용자 지시가 있을 때만** (`--major`) |
| minor | **특별한 지시가 없으면 매 개선마다 +1** |

- **시작은 `0.1`.**
- `LATEST` 파일이 최신 버전을 가리킨다. `ha-we-<id>` 를 그냥 부르면 이것이 쓰인다.
- 각 버전은 **전체 사본**이다(델타가 아니다). 옛 버전을 그대로 꺼내 쓸 수 있어야 하기 때문이다.
  텍스트 파일뿐이라 용량은 문제되지 않는다.
- 버전마다 `CHANGES.md` 에 **무엇이 바뀌었나 + 왜 바꿨나**를 적는다. `ha-we diff` 가 이것을
  파일 차이와 함께 보여 준다.

> ⚠️ **이 버전은 저장소 커밋 규약(「v3.1 커밋 체계」)과 별개 체계다.** 섞지 않는다.
> 커밋 규약은 herald-ai 저장소 자신의 커밋 번호를 매기고, 여기 버전은 배포물의 세대를 센다.

## 4. 저장소 안의 자리

```
herald-ai/
├── work-env/
│   ├── registry.json          ← 목록의 단일 출처 (ha-we list 가 읽는다)
│   └── <id>/
│       ├── LATEST             ← "0.1"
│       └── <버전>/
│           ├── manifest.json  ← 이 버전의 메타·인자·만드는 것
│           ├── CHANGES.md     ← 무엇이·왜 바뀌었나
│           └── template/      ← 실제로 뿌려질 파일들
├── bin/ha-we                  ← CLI (install.sh 가 ~/.herald/bin/ 으로 설치)
└── docs/WORK-ENV.md           ← 이 문서 (정본)
```

### 템플릿 보관 시 이름을 바꾸는 것

저장소 안에 그대로 두면 **herald-ai 자신의 설정에 섞이는** 파일이 있다. 보관용 이름으로 두고
설치할 때 되돌린다.

| 저장소 안 | 설치될 때 | 왜 |
|---|---|---|
| `template/dot-claude/` | `.claude/` | 중첩 `.claude/` 가 Claude Code 설정으로 읽힐 수 있다 |
| `template/_gitignore` | `.gitignore` | 진짜 `.gitignore` 면 herald-ai 의 git 추적에 영향을 준다 |

### 치환

템플릿 안의 `{{KEY}}` 는 설치할 때 값으로 바뀐다. **파일 내용과 경로 양쪽에** 적용된다.

| 키 | 출처 |
|---|---|
| `PROJECT_NAME` · `GOAL` · `DUE` 등 | `manifest.json` 의 `params` + CLI 인자 |
| `DATE` | 설치일 (`--date` 로 고정 가능) |
| `WE_ID` · `WE_VERSION` | 설치한 환경과 버전 — 뿌려진 디렉토리가 자기 출처를 기억하게 한다 |

## 5. 사용법

```bash
ha-we list                          # 등록된 작업환경 — 짧은 이름 + 최신 버전
ha-we versions work_ppt             # 버전 목록
ha-we show work_ppt [-v 0.1]        # 구성 내용·인자 (기본: 최신)
ha-we diff work_ppt 0.1 0.2         # 버전 간 차이 (CHANGES.md + 파일 diff)

# 뿌리기 — 기본은 모의 실행. --apply 를 줄 때만 파일을 만든다
ha-we init work_ppt ~/Desktop/새프로젝트 --name "특허 발표" --goal "..." --due 2026-12-01
ha-we init work_ppt ~/Desktop/새프로젝트 --name "..." --goal "..." --apply --with-convention

ha-we bump work_ppt -m "무엇을 고쳤나" --apply   # 최신을 복사해 다음 minor 를 연다
```

### 원칙

- **기본이 모의 실행이다.** `--apply` 없이는 아무것도 만들지 않는다.
- **기존 파일은 절대 덮지 않는다.** 이미 있으면 건너뛰고 알린다 → **재실행이 안전하다**(멱등).
- **git 은 만들지 않는다.** `git init` 위치는 동기화 수단(iCloud/Dropbox/git)과 얽힌 판단이라
  사용자가 정한다. 규약이 필요하면 `--with-convention` 으로 이어 붙인다.
- `--with-convention` 은 `herald-convention-init.sh` 를 이어 부르고, 그 스크립트가 남의
  `CLAUDE.md` 를 건드리지 않는 원칙 때문에 남기는 **수동 연결 안내를 대신 처리**한다
  (방금 `ha-we` 가 만든 `CLAUDE.md` 이므로 책임 소재가 분명하다).

## 6. 호출됐을 때 할 일

사용자가 **"ha-we 리스트"** / **"ha-we-work_ppt 로 세팅해"** / **"0.1 과 0.2 차이"** 라고 하면:

1. **목록·조회는 그대로 실행한다** — `ha-we list` · `ha-we show` · `ha-we diff` 는 읽기 전용이다.
2. **세팅 요청이면 먼저 모의 실행**으로 무엇이 만들어지는지 보여 준다.
3. **필수 인자를 묻는다** — `ha-we show <id>` 의 인자 표에서 `[필수]` 인 것.
   프로젝트 이름·목표는 추측하지 않는다.
4. 버전을 지정하지 않으면 **최신**을 쓴다. 사용자가 "0.1 로" 라고 하면 `-v 0.1`.
5. `--apply` 는 사용자 확인 뒤에 붙인다.
6. 설치 뒤 **훅은 새 세션부터 동작**한다는 것을 알린다 (첫 세션에서는 기억 복원이 안 된다).

## 7. 새 작업환경을 추가하려면

1. `work-env/<id>/0.1/` 에 `manifest.json` · `CHANGES.md` · `template/` 을 만든다.
2. `work-env/<id>/LATEST` 에 `0.1` 을 적는다.
3. `work-env/registry.json` 의 `environments` 에 한 항목을 더한다.
4. 빈 디렉토리에 `ha-we init <id> <임시경로> --apply` 로 검증한다.
5. herald-ai 저장소의 `CHANGELOG.md` · `DEVLOG.md` · `VERSION` 을 규약대로 갱신한다.

### 공개 저장소이므로 지켜야 할 것

herald-ai 는 공개 저장소다. **템플릿에 절대경로·계정명·호스트명·토큰을 넣지 않는다.**
경로를 예로 들 때는 `~/Code/herald-ai` 처럼 홈 기준으로 쓴다.
