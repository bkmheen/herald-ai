# LESSONS — 검증된 경로와 재시도 금지 경로

> **읽는 법**: 브라우저로 구글시트·구글맵을 건드리기 전에 이 파일을 먼저 훑는다.
> `⛔ 회피` 항목의 "실패한 시도" 는 **다시 시도하지 않는다**. 대체경로로 직행한다.
>
> **쓰는 법**: 새로 막히거나 뚫리면 그 자리에서 항목을 추가한다.
> 반드시 **최종확인 날짜**를 남긴다 — 외부 UI 는 바뀌므로, 오래된 항목은 재검증 대상이다.

## 상태 값

| 값 | 뜻 | 행동 |
|----|----|------|
| ✅ 검증됨 | 실제로 성공한 방법 | 그대로 쓴다 |
| ⛔ 회피 | 실패 확정. 원인 규명됨 | 재시도 금지. 대체경로 사용 |
| ⚠️ 조건부 | 특정 조건에서만 동작 | 조건 확인 후 사용 |
| 🕒 재확인필요 | 확인한 지 오래됨 / 외부 UI 개편 감지 | 쓰기 전에 1회 검증 |

## L-001 · 셀 입력 시 첫 글자(들)가 유실됨

- **상태**: ⛔ 회피 → ✅ 대체 확립 (최종확인 2026-08-01 · 리모트 맥 · 구글시트)
- **증상**: 빈 셀에 곧바로 `type "해외체류 2026 …"` 하면 앞 글자가 잘려 `2026 …` 만 들어간다.
  Tab 으로 이동한 직후 바로 `type` 하면 **값 전체가 통째로 사라지는** 경우도 있다.
- **원인 추정**: 셀 편집 모드 진입 전에 첫 키 입력이 그리드로 흘러가 소실.
- **실패한 시도**: 입력 후 재확인·재입력(값이 중복되거나 또 잘림) → 재시도 금지
- **✅ 대체경로 — 워밍업 패턴** (모든 셀 입력에 예외 없이 적용)
  1. `type "xx"` (더미)
  2. `key BackSpace BackSpace`
  3. `type <실제 값>`
  4. `key Return` 또는 `Tab`
- **검증**: 입력 후 스크린샷으로 수식 입력줄을 확인한다. 눈으로 안 본 값은 들어간 게 아니다.

## L-002 · 이름상자(Name Box) 이동이 navigate 직후 무음 실패

- **상태**: ⛔ 회피 → ✅ 대체 확립 (최종확인 2026-08-01 · 구글시트)
- **증상**: 시트 URL 로 `navigate` 한 직후 이름상자(`#t-name-box`)에 셀 주소를 넣어 이동하면
  **오류 없이 아무 데도 가지 않는다.** 그 상태로 입력하면 엉뚱한 위치에 쓰이거나
  **아무 데도 안 쓰인다**(실제로 M열 6칸 편집분이 통째로 증발한 사례).
- **실패한 시도**: 합성 `KeyboardEvent` 로 이름상자에 Enter 주입(`window.__goto` 류) — 조용히 실패.
  이 실패가 **다른 시트의 데이터를 오염**시킨 적 있다(엉뚱한 위치에 붙여넣기). → 재시도 금지
- **✅ 대체경로**
  1. 먼저 **실제 그리드 셀을 클릭**해 그리드에 포커스를 준다.
  2. 그 다음 이름상자로 이동한다.
  3. 이동 후 **스크린샷으로 현재 셀 위치를 확인**하고 나서 입력한다.

## L-003 · 합성 ClipboardEvent 붙여넣기는 신뢰 불가

- **상태**: ⛔ 회피 (최종확인 2026-08-01 · 구글시트)
- **증상**: JS 로 만든 `ClipboardEvent` 붙여넣기가 **처음 2회는 성공하고 그 뒤 실패**한다.
  페이지 리로드 후 특히 잘 깨진다. 실패해도 예외가 안 나므로 성공한 줄 알고 진행하게 된다.
- **실제 피해**: TEXTJOIN 수식 문자열이 데이터 한가운데 주입되어 시트를 `A1:Z40` 통째로
  지우고 다시 만들어야 했다.
- **실패한 시도**: 리로드 후 재시도 / 이벤트 옵션 변경 → 재시도 금지
- **✅ 대체경로**: **실제 이벤트만 사용**한다(`computer` 툴의 click·type·key).
  대량 입력은 느려도 워밍업 패턴(L-001)으로 한 셀씩 쓴다.

## L-004 · 구글맵 「저장」 대화상자가 렌더링되지 않음

- **상태**: ⛔ 회피 → ✅ 대체 확립 (최종확인 2026-08-01 · 리모트 맥)
- **증상**: 구글 **지도**(maps.google.com) 장소 카드의 「저장」을 눌러도 목록 선택
  대화상자가 뜨지 않는다. 좌측 「저장됨」 패널도 안 열린다.
- **진단 결과**: 대화상자 컨테이너 `.U2Qymb` 가 `display:flex` 이면서 `visibility:hidden`,
  크기 0×0. `Qt4aBe` batchexecute RPC 는 **200 을 반환**하는데 UI 가 생성되지 않는다.
  접근성 트리에도 노드가 없어 DOM 조작 우회도 불가.
- **실패한 시도** (총 4회, 전부 동일 결과): 좌표 클릭 / ref 클릭 / 전체 리로드 후 클릭 /
  DOM 직접 조작 → **재시도 금지**
- **✅ 대체경로**: **구글 검색(google.com)의 지식패널** 「컬렉션에 저장」을 쓴다.
  → `assets/maps-save-via-search-kp.js` (멱등 — 이미 저장돼 있으면 건드리지 않음)
- **재확인 트리거**: 구글맵 UI 개편이 눈에 띄게 감지될 때만. 그 전에는 대체경로 직행.

## L-006 · 브라우저 배치가 길면 타임아웃

- **상태**: ✅ 검증됨 (최종확인 2026-08-01)
- **증상**: `navigate + 대기 + JS 실행` 을 4개 장소분 이어붙이면 배치가 타임아웃된다.
  **타임아웃이 곧 미실행은 아니다** — 실제로는 완료돼 있던 사례가 있다.
- **✅ 방법**
  - 한 배치에 **1~3건**까지만 넣는다.
  - 실행 루틴은 반드시 **멱등**으로 짠다(이미 처리됐으면 무변경).
  - 타임아웃이 나면 같은 루틴을 다시 돌려 **상태를 조회**해서 확인한다. 무작정 재실행 말고.

## L-007 · 주소 없는 영수증의 장소 특정 논리

- **상태**: ✅ 검증됨 (최종확인 2026-08-01)
- **문제**: 영수증에 상호만 있고 주소가 없어 지도 등록 대상을 특정할 수 없는 경우.
- **✅ 절차** — 아래 증거를 모아 확정하고, 확정 못 하면 **추정으로 표기**한다.
  1. 같은 날 다른 결제들의 **도시**로 후보 지역을 좁힌다.
  2. 영수증의 **테이블 번호·POS 번호·BTW(사업자)번호**가 다른 영수증과 일치하는지 본다.
     (동일 `Tafel 3001a` 로 7/29·7/31 영수증이 같은 가게임을 확정한 사례)
  3. **우편번호 구역**으로 동명 업체를 가른다.
     (`6221 BM` = Wyck 구역 → Gronsveld(6247) 지점 배제)
  4. **직전·직후 결제와의 시간 간격**과 지도상 도보 거리를 대조한다.
     (13:42 결제 → 13:46 역 결제 = 역 앞 지점이 맞다)
  5. 그래도 남는 불확실은 **시트 「추정사항」 열에 근거를 짧게** 남긴다(L-008).
- **확정 불가 시**: `(상호 미상)` 처럼 괄호로 근거를 표기하고 지도 등록에서 제외한다.

## L-008 · 시트 열의 역할 분리 원칙

- **상태**: ✅ 검증됨 (2026-08-01 사용자 확정)
- **원칙**
  - **「구글맵 지도그룹명」 열에는 구글맵 목록명만** 넣는다. 메모·근거를 섞지 않는다.
  - 추정 근거·부가 메모는 **별도 「추정사항」 열**에 넣는다.
  - 추정사항 문구는 **짧게**(대략 30자 이내). 길면 열이 읽히지 않는다.
- **이유**: 그룹명 열이 지도 목록과 1:1 대조되는 키 역할을 해야 하는데,
  메모가 섞이면 대조가 불가능해진다.

### 「추정사항」 열을 쓰는 규칙 (2026-08-01 사용자 확정)

- **해당 사항이 있는 행에만** 쓴다. 없으면 **공란**으로 둔다. 채우기 위해 채우지 않는다.
- 한 줄만 읽어도 **무엇이 불확실한지 바로 알 수 있게** 쓴다.
  형식은 `<무엇이 미상인가> · <어떻게 판단했는가>`.
- 좋은 예:

  | 상황 | 문구 |
  |------|------|
  | 주소 없는 영수증 | `주소 미상 · 7/31과 동일 Tafel → OPEN Delft 추정` |
  | 지도에 없는 업체 | `지도 미등록 · 학회장 MECC 구내 추정` |
  | 특정 자체가 불가 | `상호·주소 미상 · 지도 등록 불가` |
  | 결제수단 미표기 | `카드번호 미표기 · 5554로 가정` |
  | 항목 불명 | `승차권 아님 · 결제 항목 불명` |

- 나쁜 예: `추정` (무엇이 추정인지 모름) · 근거를 세 줄로 늘어놓은 문장.
- 원본 셀(도시·결제수단 등)에 `(추정)`·`(가정)` 괄호 표기가 있으면
  **그 행에는 추정사항이 반드시 있어야 한다.** 괄호만 있고 설명이 없으면 누락이다.

## L-010 · 지식패널 「저장」 버튼이 UI 언어에 따라 안 잡힌다

- **상태**: ⛔ 회피 → ✅ 대체 확립 (최종확인 2026-08-19)
- **증상**: `assets/maps-save-via-search-kp.js` 가 `no save button` 을 던지며 즉시 실패한다.
  지식패널 자체는 정상적으로 떠 있다.
- **원인**: 스니펫이 `aria-label` 을 **한국어 문자열로만** 찾았다
  (`컬렉션에 저장|저장됨`). 구글 검색은 계정·지역 설정에 따라 UI 언어가 달라지고
  (`document.documentElement.lang` 이 `en-KR` 인 실측 사례), 이때 라벨은
  `Save <상호> to collection` · `Saved – <상호>` 다.
- **✅ 대체경로**: 정규식을 언어 양쪽으로 넓힌다.

  ```js
  const RE = /컬렉션에 저장|저장됨|to collection|^Saved\b/;
  ```

  같은 이유로 **닫기 버튼**도 `닫기|^Close$` 로 둘 다 본다.
- **덤**: 라벨이 안 잡히면 원인을 추측하지 말고 **현재 라벨 목록을 먼저 덤프**한다.
  이 한 줄이면 언어·구조가 즉시 드러난다.

  ```js
  [...document.querySelectorAll('[role="button"],button')]
    .map(e => e.getAttribute('aria-label')).filter(Boolean)
  ```

- **주의**: 저장·저장됨 두 버튼이 **동시에 DOM 에 존재**한다(토글 양쪽 상태).
  보이는 쪽(`getBoundingClientRect().width > 0`)을 고르되, 애니메이션 중에는 둘 다
  0×0 일 수 있으므로 **없으면 첫 번째로 폴백**한다.

## L-011 · 컬렉션 핀에 메모를 다는 절차 — 대화상자 애니메이션 함정

- **상태**: ✅ 검증됨 (최종확인 2026-08-19)
- **왜 필요한가**: 핀만 저장하면 지도는 "여기 갔었다" 까지만 말한다. 메모에 날짜·금액·
  노트 UID 를 넣어야 **지도 → 노트 역참조**가 성립한다. 노트의 `[MAPS_REGISTERED]` 마커와
  쌍을 이루는 반대 방향 링크다.
- **✅ 절차** (저장된 목록 페이지 `.../interests/saved/list/<컬렉션 id>` 에서)
  1. 핀의 `추가 옵션 for <장소명>` 버튼 클릭
  2. 뜬 메뉴에서 **보이는** `수정` 항목 클릭 (같은 문구의 숨은 메뉴가 핀 수만큼 있다)
  3. 대화상자에 입력칸 **2개** — 위가 **제목**(120자), 아래가 **메모 추가**(280자)
  4. 메모칸 클릭 → 입력 → `완료`
  5. 목록 페이지를 **리로드**해야 메모 칩이 보인다. 저장 직후 DOM 에는 안 나타난다
- **⛔ 함정 — 대화상자가 페이드인 중에는 좌표가 다르다.** 애니메이션 도중 좌표로 클릭하면
  **제목칸에 메모가 들어간다.** 제목은 120자에서 잘리므로 원래 상호명이 파괴된다.
  배경을 눌러 대화상자가 그냥 닫히는 경우도 있다(입력은 증발).
  - 실측: 정착 전 `y≈383/451` → 정착 후 `y≈475/555` (같은 창에서 70px 이동)
- **✅ 방법**: 대화상자를 연 뒤 **3초 대기 → 스크린샷 → 좌표 확인 → 클릭**.
  입력 후 `완료` 를 누르기 전에 두 칸의 값을 반드시 검증한다.

  ```js
  const vis = e => { const r = e.getBoundingClientRect(); return r.width > 0 && r.height > 0; };
  [...document.querySelectorAll('input,textarea')].filter(vis).map(e => e.value)
  // → ["<상호명>", "<메모>"] 이어야 한다. 뒤바뀌었으면 되돌리고 다시 한다
  ```

- **되돌리기**: `완료` 전이라면 제목칸에서 `cmd+a` → 원래 상호명 재입력으로 복구된다.
  아직 저장되지 않았으므로 목록은 무사하다.
- **메모 서식** (한 핀에 여러 번 방문했으면 한 줄에 합친다)

  ```
  YYYY-MM-DD(요일) HH:MM · €금액 · 내역 요약 [UID_...]
  YYYY-MM-DD(요일) HH:MM·HH:MM · 합계 €금액 · 내역 [UID_...][UID_...]
  ```

## L-012 · 탭이 백그라운드면 구글시트 키보드 입력이 전부 무음 실패한다

- **상태**: ⛔ 회피 (최종확인 2026-08-19)
- **증상**: 시트가 화면에 멀쩡히 보이는 스크린샷이 찍히고, 셀 클릭도 먹는다
  (선택 셀이 실제로 바뀐다). 그런데 **키보드만 전부 무시된다** — 이름상자 입력,
  방향키 이동, 값 타이핑, 붙여넣기 모두 오류 없이 아무 일도 일어나지 않는다.
- **원인**: 그 탭이 창의 활성 탭이 아니거나 창 자체가 최소화·가려져 있어
  `document.visibilityState === 'hidden'` 인 상태. 구글시트는 숨은 탭에서 키 이벤트를 버린다.
  스크린샷은 렌더 결과라 **보인다고 해서 전면인 것이 아니다.**
- **⛔ 재시도 금지**: 새 탭 생성·재내비게이트·`resize_window` 모두 상태를 바꾸지 못했다
  (3회 확인). 확장 쪽에서 탭을 전면화할 방법이 없다.
- **✅ 진단** — 시트에 무엇이든 쓰기 전에 **먼저 한 줄로 확인한다.**

  ```js
  JSON.stringify({ vis: document.visibilityState, hasFocus: document.hasFocus() })
  // vis 가 "hidden" 이면 입력 단계로 들어가지 말 것
  ```

- **✅ 대응**: 사용자에게 **크롬 창을 전면으로 올려 달라고 요청**하고 기다린다.
  그 사이에 할 수 있는 일(붙여넣을 TSV 블록 준비, 볼트 쪽 갱신)을 먼저 끝내 둔다.
- **주의**: `hasFocus()` 는 숨은 탭에서도 `true` 로 나올 수 있다. **`visibilityState` 를 본다.**

## L-013 · 스크린샷 좌표가 곧 클릭 좌표가 아니다

- **상태**: ✅ 검증됨 (최종확인 2026-08-19)
- **증상**: 스크린샷에서 읽은 좌표로 클릭했는데 다른 셀·다른 요소가 선택된다.
  빗나가는 정도가 창 크기마다 다르다.
- **원인**: 스크린샷은 상한에 맞춰 **축소되어** 돌아올 수 있는데, 클릭 좌표는
  **뷰포트 CSS 픽셀**로 해석된다. 두 좌표계의 배율이 1 이 아니면 그만큼 어긋난다.
  - 실측: `innerWidth 1280` → 스크린샷 폭 `1139` (배율 0.89, 화면 아래로 갈수록 오차 누적)
  - 실측: `innerWidth 1440` → 스크린샷 폭 `1456` (배율 ≈1.01, 사실상 일치)
- **✅ 방법 1 (권장)**: 좌표를 눈으로 재지 말고 **DOM 에서 받는다.**

  ```js
  const r = document.querySelector('<선택자>').getBoundingClientRect();
  ({ x: Math.round(r.x + r.width / 2), y: Math.round(r.y + r.height / 2) })  // 그대로 클릭 좌표
  ```

- **✅ 방법 2**: 배율을 먼저 재고 환산한다 — `innerWidth ÷ 스크린샷 폭`.
- **✅ 방법 3 (그리드)**: 시트 셀은 좌표로 찍지 말고 **키보드로 이동**한다
  (셀 하나 클릭 → 방향키). 단 L-012 를 먼저 확인할 것.
