# trip-ledger — 여행·출장 지출 원장 파이프라인

## 이 스킬의 존재 이유

같은 작업을 다른 Mac 에서 다시 할 때, **이미 막혔던 길을 다시 가지 않기 위해서**다.
발견한 우회로는 `LESSONS.md` 에 즉시 적고, 다음 작업은 그 기록에서 출발한다.

herald-ai 는 git 으로 배포되므로 어느 Mac 이든 `git pull && bash install.sh` 하면
같은 수준의 노하우를 갖는다. **머신 로컬 메모리에 남기지 말고 반드시 이 스킬에 적어라.**

---

## ⛔ 0단계 — 실행 맥 판정 (모든 작업의 첫 단계, 예외 없음)

볼트(`노트볼트`)는 **서버 맥 → 다른 맥으로 흐르는 단방향(one-way) 미러**다.
리모트 맥에서 볼트를 고치면 충돌이 나는 게 아니라 **다음 미러 때 조용히 사라진다**
(`rsync --delete`, 역방향 채널 없음).

```bash
ls -ld ~/볼트상위
```

| 결과 | 판정 | 볼트 권한 |
|------|------|-----------|
| **실디렉토리** (`drwx…`) | **서버 맥** (미러 원본) | **읽기·쓰기** |
| **심볼릭 링크** (`lrwx… -> …/Documents/볼트상위`) | **리모트 맥** (미러 수신본) | **읽기 전용 ⛔** |

리모트 맥에서 볼트 수정이 필요해지면 **직접 고치지 말고 §5 인계 프로토콜**로 넘긴다.

### 대상별 쓰기 권한 매트릭스

| 대상 | 리모트 맥 | 서버 맥 | 근거 |
|------|:---------:|:-------:|------|
| 볼트 `노트볼트/…` (노트·앤솔로지·Registry) | **읽기 전용 ⛔** | 쓰기 | 단방향 미러 |
| 구글시트 · 구글맵 | 쓰기 | 쓰기 | 클라우드 — 맥 무관 |
| herald-ai (`~/Code/herald-ai`) | 쓰기(git) | 쓰기(git) | git pull/push 양방향 |
| 바탕화면 인계 md (`~/Desktop`) | **쓰기(발신)** | **읽기(수신)** | iCloud Desktop 동기화 |

> 리모트 맥이라고 아무것도 못 하는 게 아니다. **클라우드 쪽(시트·맵)은 전부 가능**하고,
> **볼트 쓰기만 불가**하다. 이 비대칭이 아래 단계 배분의 핵심이다.

---

## 1단계 — 레지스트리 조회 (어느 맥에서나 · 읽기)

프로젝트(여행 1건)의 시트 ID·맵 목록명·앤솔로지 UID 는 **볼트에** 있다.
herald-ai 는 **공개 저장소**이므로 이런 식별자를 절대 커밋하지 않는다.

```
~/볼트상위/노트볼트/Dossier/Registry/
  Registry.md                  # 폴더 노트 (Anthologies.md 와 동일 패턴)
  RG_여행지출/
    <프로젝트키>.yaml          # 예: 260700-여름휴가-델프트.yaml
```

스키마는 `registry.example.yaml` 참조. 없으면 §5 로 서버 맥에 생성을 요청한다.

### 볼트 안에서의 표시 규약

앤솔로지(여행 1건 = 링크그룹 대표 노트)의 frontmatter 에만 아래를 단다.

```yaml
areas:
- '[[AR_시스템-지출원장]]'      # 이 앤솔로지가 이 파이프라인 소관임을 표시
tags:
- 지출원장
```

- **영역은 하나뿐이다. 여행별로 쪼개지 않는다** — 어느 여행인지는 앤솔로지 자신이 말한다.
- **개별 영수증 노트에는 붙이지 않는다.** 그 노트들은 다른 provenance 영역에
  단독 귀속돼 있을 수 있고, 영역을 겹쳐 달면 그 규칙이 깨진다.
- 영역 이름은 **볼트의 기존 명명 관례를 따른다**(임의로 영문·언더스코어를 쓰지 말 것).
- 영역을 새로 만들 때는 **어휘 등록 파일(kb_areas 등)에도 등록**해야 엔진이 인식한다.
  자동 배정을 원하지 않으면 키워드는 비워 두고 수동 귀속 전용으로 만든다.
- 앤솔로지에 영역을 다는 것은 볼트에 따라 **엔진이 지원하지 않는 용법**일 수 있다.
  자동 목록에 안 뜨더라도 위키링크이므로 **백링크로는 보인다.** 그걸로 충분한지
  먼저 확인하고, 엔진 변경은 별도 건으로 분리한다.

## 2단계 — 노트 수집·정리 (**서버 맥 전용**)

영수증 → `Dossier/Archive/<대분류>/<소분류>/` 노트 → 앤솔로지 링크그룹 편입.
→ `playbooks/10-notes.md`

리모트 맥에서는 **읽기만** 가능하다. 노트 생성·수정·마커 기록은 전부 §5 인계 대상.

## 3단계 — 구글시트 원장 (어느 맥에서나)

시트 구조 표준(열 정의·틀고정·열 폭·원화 병기)은 `playbooks/20-sheets.md`,
열 스펙 원본은 `assets/sheet-columns.md`.

---

## 4단계 — 구글맵 목록 등록 (어느 맥에서나)

절차와 검증된 우회로는 `playbooks/30-maps.md`.
**지도 「저장」 대화상자를 직접 클릭하려 하지 마라 — L-004 참조.**

등록 후 각 노트에 마커를 남기는 일은 **볼트 쓰기**이므로 §5 인계 대상이다.

```
[MAPS_REGISTERED] <노트 uid> -> "<구글맵 목록명>" / <장소명>
```

## 5단계 — 인계 프로토콜 (리모트 맥 → 서버 맥)

리모트 맥에서 볼트 수정이 필요할 때의 **유일한 합법 경로**다.

1. `~/Desktop/YYMMDD [작업지시] <제목>.md` 로 작성한다.
   - iCloud 데스크톱 동기화로 서버 맥에 자동 도착한다(별도 전송 불필요).
2. 문서에 반드시 포함할 것:
   - **어느 맥에서 무엇을 이미 끝냈는지**(재작업 방지)
   - **서버 맥이 해야 할 일**을 파일 경로·정확한 문자열까지 확정해서
   - **왜 리모트에서 못 했는지**(0단계 판정 결과)
   - 완료 후 미러 실행 지시 (`노트볼트/scripts/미러스크립트.sh --auto`)
3. 서버 맥에서 반영·미러까지 끝나면 지시서를 `[작업완료]` 로 개명하거나 회수한다.

> **금지**: 리모트 맥에서 볼트에 쓰고 "나중에 서버에서 맞추면 되겠지" 하는 것.
> 미러가 `--delete` 로 덮으므로 변경분이 예고 없이 사라진다.

---

## 6단계 — 배운 것 기록 (모든 작업의 마지막, 예외 없음)

이번 작업에서 **새로 막힌 것 / 새로 뚫린 것**이 있으면 그 자리에서 적는다.

- 브라우저·외부 UI 관련 → `LESSONS.md`
- 절차·표준 자체가 바뀜 → 해당 `playbooks/*.md`
- 기록 후 `VERSION` patch↑ + 커밋 (herald-ai `CLAUDE.md` 규칙 준수, **push 는 요청 시에만**)

기록하지 않으면 다음 맥에서 같은 벽에 같은 시간을 쓴다. 이것이 이 스킬의 핵심 목적이다.
