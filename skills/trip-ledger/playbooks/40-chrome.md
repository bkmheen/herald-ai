# 40 · 브라우저 조작 공통 기법

> 개별 실패 사례와 그 원인은 `LESSONS.md` 에 있다. 여기는 **매번 지키는 습관**만 적는다.

## 세션 시작

1. `tabs_context_mcp` 로 현재 탭을 먼저 본다. 이전 세션의 탭 ID 를 재사용하지 않는다.
2. 사용자가 특정 탭을 지목하지 않았으면 **새 탭**을 만든다.
3. 툴이 "탭 없음/무효" 오류를 내면 곧바로 `tabs_context_mcp` 로 새 ID 를 받는다.

## 입력 전 — 탭이 정말 전면인지 먼저 본다

스크린샷이 멀쩡히 찍히고 클릭도 먹는데 **키보드만 통째로 무시되는** 상태가 있다.
탭이 백그라운드일 때다. 쓰기 전에 한 줄로 확인한다 (L-012).

```js
JSON.stringify({ vis: document.visibilityState, hasFocus: document.hasFocus() })
```

`vis` 가 `"hidden"` 이면 **입력 단계로 들어가지 않는다.** 확장 쪽에서 전면화할 방법이
없으므로 사용자에게 창을 올려 달라고 요청하고, 그 사이 준비 작업을 끝내 둔다.
`hasFocus()` 는 숨은 탭에서도 참일 수 있으니 판정 근거로 쓰지 않는다.

## 입력의 3원칙

1. **실제 이벤트만 쓴다.** 합성 `ClipboardEvent`·`KeyboardEvent` 는 조용히 실패한다(L-002·L-003).
2. **워밍업 후 입력한다.** `type "xx"` → `BackSpace ×2` → 실제 값 (L-001).
3. **눈으로 확인한 것만 들어간 것이다.** 입력 후 스크린샷으로 수식 입력줄·셀 위치를 본다.

## 위치 이동

- `navigate` 직후에는 **실제 그리드 셀을 클릭**해 포커스를 준 다음 이동한다(L-002).
- 이동 후 위치를 확인하고 나서 입력한다. 확인 없이 쓰면 데이터가 오염된다.
- **스크린샷에서 눈으로 잰 좌표를 그대로 쓰지 않는다.** 스크린샷은 축소되어 올 수 있고
  클릭은 뷰포트 CSS 픽셀로 해석된다 — 배율이 다르면 어긋난다 (L-013).
  좌표는 `getBoundingClientRect()` 로 받거나, 그리드는 방향키로 이동한다.

## 배치 구성

- 한 배치에 **1~3 작업**. 길면 타임아웃(L-006).
- 모든 루틴은 **멱등**으로 짠다 — 재실행해도 상태가 안 망가져야 재확인이 가능하다.
- 타임아웃은 실패가 아니다. **상태를 조회**해서 판정한다.

## 대화상자 금지

`alert`·`confirm`·`prompt` 를 띄우는 조작을 하지 않는다. 뜨면 확장이 먹통이 되어
사용자가 직접 닫아야 한다. 디버깅은 `console.log` + `read_console_messages` 로 한다.

## 막혔을 때 — 2~3회 규칙

같은 조작이 **2~3회 실패하면 멈춘다.** 변형해 가며 계속 시도하지 않는다.

1. 무엇을 시도했고 무엇이 나왔는지 정리한다.
2. `LESSONS.md` 에 이미 있는 벽인지 확인한다.
3. 없으면 **새 항목으로 기록**하고 사용자에게 판단을 구한다.

이 규칙이 없으면 같은 벽에 같은 시간을 반복해서 쓰게 된다. 그걸 막는 게 이 스킬의 목적이다.

## 사용자가 브라우저를 만졌다는 신호가 있으면

이어서 하지 말고 페이지를 리로드하고 현재 상태를 스크린샷으로 재확인한 뒤 다시 시작한다(L-009).
