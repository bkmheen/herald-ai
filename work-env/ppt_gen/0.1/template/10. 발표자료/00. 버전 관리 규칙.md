# 산출물 버전 관리 규칙

- 제정일: {{DATE}}
- 적용 범위: `{{DELIVERABLE_DIR}}/` 하위 모든 파일

## 1. 파일명 형식

```
v{버전코드} {대표 변경사항}.{확장자}
```

- 예: `v0.1 초안 구조.pptx`, `v0.2 아이디어 3안 비교 추가.pptx`
- **버전코드**: `0.1`, `0.2`, … 형식. 구조·내용의 큰 변화 시 앞자리(`1.0`) 승격.
- **대표 변경사항**: 이전 버전 대비 핵심 변경 한 구절.

## 2. 소스 동기화 원칙 (pptx ↔ md/소스)

- pptx 를 생성할 때는 **동일한 파일명(확장자만 다름)** 으로 그 내용의 소스를 함께 저장한다.
  - 예: `v0.1 초안 구조.pptx` + `v0.1 초안 구조.md` (+ 필요 시 `.py`, `.html` 등 생성 스크립트)
- md 파일은 슬라이드별 제목·본문·발표자 노트를 담아 **pptx 를 열지 않아도 같은 내용을 읽을 수
  있게** 작성한다.
- pptx 가 바뀌면 같은 버전의 md 도 반드시 함께 갱신한다. **둘의 내용이 어긋난 상태로 남기지 않는다.**

## 3. 사용자 수동 수정 버전 (`v0.1a` 형식)

- 사용자가 pptx 를 직접 수정한 경우, 버전코드 뒤에 소문자(`a`, `b`, …)를 붙여 저장한다.
  - 예: `v0.1a 결론 슬라이드 문구 수정.pptx`
- Claude 는 해당 파일을 읽어 **직전 버전과의 차이를 파악**하고, 그 내용을 `{{PROGRESS_DIR}}/` 에
  기록한 뒤 의견을 주고받는다.
- 사용자 수정 사항을 반영한 다음 Claude 버전은 기본 버전코드를 올린다 (`v0.1a` → `v0.2`).
