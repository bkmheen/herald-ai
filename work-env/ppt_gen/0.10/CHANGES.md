# ha-we-ppt_gen v0.10

- 일자: 2026-09-30
- 이전: v0.9

## 무엇이 바뀌었나

**v0.9 가 넣은 생성기의 렌더링 결함 세 건을 고쳤다.** 규칙도 구조도 그대로이고,
`template_2609.py` 의 동작만 바로잡았다.

### 결함 1 — 표와 코드 상자의 **순서가 뒤집혔다**

`.md` 에 **표 → 코드펜스** 순으로 써도 pptx 에는 **코드 상자가 표보다 위에** 그려졌다.

파서가 표를 **대기 버퍼**에 모아 두었다가 "표가 아닌 줄" 을 만날 때 비우는데,
**코드펜스 줄은 그 분기를 타지 않고** 곧장 코드 항목을 `append` 했기 때문이다.

→ 펜스의 **시작·종료 양쪽**에서 대기 중인 표를 먼저 비우도록 고쳤다.

### 결함 2 — 코드 상자 안의 **줄이 겹쳐 보였다**

코드 상자는 AutoShape 로 그리는데, AutoShape 의 텍스트는 기본이 **가운데 정렬 + 세로 가운데**
라 여러 줄이 상자 중앙으로 몰려 어긋나 보였다.

→ `vertical_anchor = TOP` · `alignment = LEFT` · `word_wrap = False` 로 고정했다.

### 결함 3 — `*기울임*` 이 **별표째 찍혔다**

`inline()` 이 `**굵게**` 와 `` `코드` `` 만 런으로 갈라서, 논문 인용에 쓴 `*"…"*` 가 별표를
포함한 채 그대로 표시됐다.

→ `*…*` 을 런으로 갈라 `font.italic = True` 를 주도록 고쳤다.

### 골격 md 와 README

- `template_2609.md` 의 「계산을 보여 주는 슬라이드」에 **표를 먼저 두고 그 뒤에 코드펜스**를
  두었다. 코드 블록도 **두 줄**로 늘렸다. 그리고 불릿 하나를 `*기울임*` 으로 썼다.
  → **골격 자체가 세 결함의 회귀 시험**이 된다. 템플릿을 한 번 돌려 보면 드러난다
- `README.md` 의 md 문법 표에 **`*기울임*`** 을 넣고, 코드 블록 줄에 **"쓴 순서대로 — 표 뒤에
  쓰면 표 아래에 온다"** 를 명시했다

## 왜 바꿨나

**v0.9 의 취지가 "규칙을 실행하는 코드를 함께 준다" 였다.** 그렇다면 그 코드가 틀리면
**규칙을 쓰는 모든 프로젝트가 같은 방식으로 틀린다.** 문서의 오타와 다르다.

특히 결함 1 은 **내용의 정합성을 깬다.** 표로 구성을 보이고 그 표에서 나온 수를 코드 상자로
계산하는 슬라이드에서, 계산이 표보다 먼저 나오면 **어디서 나온 수인지 알 수 없다.**
결함 2 도 같다 — `352 ÷ 10 = 35.2배` 가 다른 줄과 겹치면 읽을 수 없다.

**발견 경위.** 생성한 pdf 를 이미지로 렌더해 눈으로 확인하다가 나왔다. 생성기는 넘침 경고만
내고 **순서와 정렬은 검사하지 않는다.** 그래서 이번에 **골격 md 가 세 경로를 모두 밟도록**
바꿨다 — 다음부터는 템플릿을 한 번 돌려 보는 것만으로 회귀가 드러난다.

## 이관 시 주의

v0.9 로 만든 디렉토리에 v0.10 을 다시 뿌려도 **기존 파일은 덮지 않는다**(멱등).
아래 세 파일을 **손으로 옮겨야** 한다.

- `.llm/templates/template_2609/template_2609.py` (세 곳)
- `.llm/templates/template_2609/template_2609.md` · `README.md`

⛔ **이미 만들어 둔 산출물은 소급해 같은 버전으로 다시 만들지 않는다.**
`.py` 를 고치면 그 버전의 pptx 와 어긋나므로, **다음 버전을 올릴 때 함께** 반영한다.
그 자료를 당분간 올릴 계획이 없다면 **그 자료의 생성기는 그대로 두는 편이 낫다** —
네 파일(`pptx`·`pdf`·`md`·`py`)이 서로 맞는 상태가 규칙이기 때문이다.
