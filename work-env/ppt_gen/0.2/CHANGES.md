# ha-we-ppt_gen v0.2 — work_ppt 를 흡수해 이름을 바꾸고, 여러 LLM 협업 구조를 더했다

- 일자: 2026-09-29
- 직전 버전: v0.1 (**이전 이름 `work_ppt`**)
- 출처: `work_ppt` v0.1 + `260927_docs` (스크린샷 기반 가이드 매뉴얼 4종 프로젝트)

## 왜 이름을 바꿨나

`work_ppt` 는 "발표자료 만들기" 였다. 사람이 백지에서 슬라이드를 쓰는 작업을 전제한다.
그런데 실제로 필요했던 일은 **원본 자료(스크린샷 묶음·PDF)를 재료로 PPT 를 생성**하는
것이었고, 그 과정을 **여러 LLM 이 각자 만들어 비교하고 이어받는** 형태로 돌렸다.

`ppt_gen` 은 그 상위 개념이다 — 산출물은 같은 pptx 지만 **일의 모양이 다르다.**
`work_ppt` 의 목표는 `ppt_gen` 에 포함되므로 별도 환경으로 두지 않고 흡수했다.

v0.1 은 이 디렉토리에 **그대로 남겨** 옛 판을 꺼내 쓸 수 있게 했다 (`ha-we show ppt_gen -v 0.1`).

## v0.1 에서 가져온 것

| 구성 | 왜 |
|---|---|
| `CLAUDE.md` 세션 시작 절차 | 대화 기록이 컴퓨터 간에 동기화되지 않는다 — 이어받는 방법이 디렉토리 안에 있어야 한다 |
| 산출물 버전 규칙 | 같은 물건의 버전을 갈아 끼운다 |
| pptx 와 동명 소스를 쌍으로 | 사용자는 pptx 를 보지만 내용 파악은 텍스트로 빠르게 하고 싶어 한다 |
| 사용자 수동 수정 버전 (`v0.1a`) | 사람이 고친 것을 따로 세고 차이를 읽는다 |
| `_gitignore` | 컴퓨터별 임시 상태 제외 |
| 응대 원칙 | 존댓말·사실 그대로 보고·task-tracker |

## v0.2 에서 바꾼 것

### 1. 기억을 디렉토리 자족으로 — `sync-memory.sh` 를 버렸다

v0.1 은 홈의 `~/.claude/projects/<slug>/memory/` 와 프로젝트 사본을 훅으로 양방향
동기화했다. 슬러그를 경로에서 계산해 어느 맥에서도 대응하게 만든 영리한 방법이지만,
**Claude 전용**이고 **홈에 기억이 남는다.**

v0.2 는 `.llm/` 안에만 기억을 둔다. 홈과의 동기화가 없으므로 훅도 없다.

| | v0.1 | v0.2 |
|---|---|---|
| 기억 위치 | 홈 + 프로젝트 사본 | **프로젝트만** |
| 동기화 | SessionStart/Stop 훅 | 없음 (필요 없다) |
| 대상 도구 | Claude | **Claude · Gemini · Codex …** |
| 이식 | 훅이 슬러그를 계산해 대응 | 아예 홈을 쓰지 않아 대응할 것이 없다 |

대가 — Claude 의 기본 동작(홈 memory 에 쓰기)을 **지시로 막는다.** 진입점 문서에
"홈에는 남기지 않는다" 를 명시했다. 훅으로 강제하지 않은 이유는 다른 컴퓨터에서
예상치 못한 동작을 일으킬 위험이 있고, 자동 로드되는 진입점 지시로 충분하기 때문이다.

### 2. 여러 LLM 이 한 디렉토리에서 — 공용과 개별을 나눴다

```
source/              모두가 읽는 원본 (읽기 전용)
.llm/BOARD.md        ★ 누가 어디까지 했는가 — 인계의 접점
.llm/memory/         공용 기억 (모두 읽고 쓴다)
.llm/sessions/       공용 세션 기록
.llm/agents/<llm>/   LLM 개별 기억·기록 (자기 것만 쓴다)
<llm>/               LLM 작업공간 + STATUS.md + __history__/
```

- **`BOARD.md` 가 핵심이다.** LLM 별 최신 산출물·어디까지·다음 할 일·갱신일을 한 표에
  둔다. 작업을 마칠 때 자기 줄을 갱신하는 것이 규칙이고, 이것을 빠뜨리면 인계가 끊긴다.
- **공용과 개별의 경계는 한 질문으로 정한다** — "다른 LLM 이 이어받을 때 알아야 하나?"
  예면 공용, 아니면 개별. 판단 근거는 거의 항상 공용이다.
- **개별 기억도 `.llm/` 안에 둔다.** 남의 것도 읽을 수 있어야 이어받을 수 있기 때문이다.
  쓰기만 자기 것으로 제한한다.
- **쓰기 경계를 표로 못 박았다.** 원본은 아무도 못 쓰고, 남의 작업공간·남의 `agents/` 는
  읽기만 한다. 이어받을 것은 **자기 작업공간으로 복사**해 진행한다.

### 3. 진입점을 도구별로 세 개

`CLAUDE.md` · `GEMINI.md` · `AGENTS.md`. 내용은 같고 자기 경로만 다르다.
각 도구가 **작업 디렉토리 기준으로** 자동 로드하므로, 디렉토리를 옮겨도 따라간다.

### 4. 원본 디렉토리를 규약으로

`source/` (인자로 변경 가능)를 두고 **읽기 전용**으로 못 박았다. 이미지 묶음이든 PDF든
같은 자리에서 읽는다. 축소판만 보고 원본을 제외하지 말라는 주의도 넣었다 —
흐릿해 보였던 것이 원본 크기에서는 선명한 경우가 있었다.

### 5. 이관 작업절차를 문서로

옮기거나 복사하는 작업도 LLM 이 한다. `50_이관_작업절차.md` 에 A 정리 → B 복사 →
C 환경 → D 검증 → E 주의를 실행 가능한 명령과 함께 적었다.
`.llm/` 이 숨은 디렉토리라 Finder 드래그에서 빠질 수 있다는 것을 금지사항으로 명시했다.

### 6. 산출물 버전에 `__history__/` 를 더했다

v0.1 은 파일명으로만 버전을 구분했다. v0.2 는 **최종 버전 한 벌만 작업공간에 두고**
이전 버전을 `__history__/` 로 옮기며, 버전마다 `_CHANGE.md` 에 **왜 바꿨나**를 남긴다.

## 도구 쪽 변경

`bin/ha-we` 의 보관용 이름 되돌리기가 `dot-claude` 만 처리하도록 하드코딩되어 있어
`dot-llm/` 이 `.llm/` 으로 펼쳐지지 않았다. **`dot-<name>` → `.<name>` 을 경로 어느
자리에서나** 적용하도록 일반화했다. 기존 `dot-claude` 동작은 그대로다.

## 알려진 한계

- **생성 엔진은 담지 않았다.** 원본 프로젝트의 OCR·마스킹·슬라이드 엔진은 Apple Vision
  (macOS 전용)과 그 프로젝트의 규칙에 묶여 있다. 템플릿에 넣으면 이식성이 깨지고
  "PPT 생성" 이라는 넓은 목표를 스크린샷 파이프라인으로 좁힌다.
  엔진을 함께 배포할지는 별도 판단으로 남긴다.
- **git 은 만들지 않는다** (v0.1 과 같다). `git init` 위치는 동기화 수단과 얽힌 판단이라
  사용자가 정한다. 규약이 필요하면 `--with-convention` 으로 이어 붙인다.
- `ha-we` 의 디렉토리 이름 치환에 v0.1 용 한글 디렉토리명 세 개가 아직 하드코딩되어 있다.
  ppt_gen 0.2 는 `{{...}}` 인자로 경로를 만들므로 영향이 없다.
