# ha-we-ppt_gen v0.3 — 입력 자료를 주인에 따라 두 층으로 나눴다

- 일자: 2026-09-29
- 직전 버전: v0.2

## 왜

v0.2 는 입력 자료를 한 층으로만 봤다 — `{{SOURCE_DIR}}/`, 읽기 전용. 그런데 실제로 일을
하면 **LLM 이 자료를 만들어야 하는** 경우가 생긴다. PDF 에서 페이지를 뽑거나, 조사해 정리한
것을 두거나, 변환한 중간 자료를 다른 LLM 도 쓰게 두는 경우다.

그때 둘 곳이 없었다. 사용자 자료 디렉토리에 두면 **읽기 전용 원칙을 깨고**, 자기 작업공간에
두면 다른 LLM 이 **입력인지 출력인지 구분하지 못한다.**

## 무엇을 바꿨나

**이름이 아니라 주인으로 가른다.**

| 층 | 주인 | LLM 의 권한 | 무엇이 들어가나 |
|---|---|---|---|
| `{{SOURCE_DIR}}/` | **사용자** | ⛔ 읽기만 | 사용자가 포함한 자료 |
| `reference/` | **LLM** | ○ 기록을 남기는 조건으로 자체 관리 | LLM 이 필요해서, 또는 요청받아 만들거나 모은 자료 |

### 기록이 관리 권한의 조건이다

`reference/` 는 LLM 이 만들고 고치고 지울 수 있다. 대신 `reference/README.md` 의 대장에
**무엇을 · 언제 · 누가 · 왜 · 어디서 왔는지** 남긴다.

권한만 주고 기록을 요구하지 않으면, 다음 세션(또는 다른 LLM)이 그 자료의 출처를 알 수 없어
**쓸 수 없는 자료**가 된다. 자유롭게 관리하게 하는 대가로 기록을 조건으로 걸었다.

### 디렉토리 이름은 사용자가 정한다

`{{SOURCE_DIR}}` 은 인자다. **사용자가 다른 이름의 디렉토리를 지정하면 그것이 사용자 자료
디렉토리**다. 이름이 `source` 가 아니어도 같은 규칙이 적용된다 — 주인이 사용자이므로 읽기만
한다. 여럿이면 전부 사용자 자료로 취급하고 `20_자료_규칙.md` 의 표에 적어 둔다.

실제로 `260927_docs` 는 `shared_image_org/` 를 쓰고 있다. 규칙 정본이 그 이름을 문서화했고
다른 LLM 의 스크립트가 참조하기 때문이다. 이름을 강제하지 않는 것이 이런 경우를 살린다.

### `reference/` 와 작업공간의 차이

| | `reference/` | `<llm>/` |
|---|---|---|
| 성격 | **입력** — 만드는 데 쓰는 재료 | **출력** — 만든 결과 |
| 쓰기 | 모든 LLM (대장 기록 조건) | 주인만 |

자기만 쓰는 중간 산출물은 `reference/` 가 아니라 자기 작업공간에 둔다.
이 경계를 흐리면 `reference/` 가 잡동사니가 되고 아무도 신뢰하지 않게 된다.

### 사용자가 `reference/` 에 직접 넣은 것

**그것은 사용자 자료다.** 대장에 "사용자 제공" 으로 적고 그 항목은 읽기만 한다.
주인이 기준이라는 원칙을 그대로 적용한 것이다. 대장의 '만든 LLM' 칸으로 구분된다.

## 바뀐 파일

| 파일 | 변경 |
|---|---|
| `reference/README.md` | **신설** — 자료 대장 + 두는 법 + 하지 않는 것 |
| `.llm/memory/20_자료_규칙.md` | `20_원본자료_규칙.md` 를 **대체**. 두 층의 권한과 판단 기준 |
| `CLAUDE.md` · `GEMINI.md` · `AGENTS.md` | 디렉토리 규칙 표에 주인·쓰기 권한 열 추가 |
| `.llm/memory/01_프로젝트_개요.md` | 입출력 표를 3행(사용자 입력·LLM 입력·출력)으로 |
| `.llm/memory/40_LLM_협업_규칙.md` | 쓰기 경계 표에 `reference/` 추가 |
| `.llm/memory/50_이관_작업절차.md` | 반드시 포함할 것에 `reference/` 추가 |
| `<SOURCE_DIR>/README.md` | "원본 자료" → "**사용자** 자료" 로 성격 명시 |

## 알려진 한계

- **`reference/` 는 빈 디렉토리로 뿌려진다** (README 만 있다). 당장 쓸 자료가 없어도
  자리를 먼저 만들어 두는 편이 낫다고 봤다 — 필요해질 때 어디 둘지 고민하지 않게 된다.
- 대장 갱신은 **강제할 수단이 없다.** 훅으로 막을 수도 있지만 v0.2 에서 훅을 버린 이유와
  같다 — 자동 로드되는 진입점 지시로 충분하다고 보고, 규칙을 세 곳(진입점·자료 규칙·
  `reference/README.md`)에 적어 빠뜨리기 어렵게 했다.
