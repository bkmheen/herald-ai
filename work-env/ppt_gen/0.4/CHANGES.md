# ppt_gen v0.4 — 자료에 번호를 붙인다

작성 2026-09-29 · 직전 v0.3

## 무엇이 바뀌었나

자료마다 **두 자리 번호**를 붙이는 규칙을 명문화했다. 새 기억 문서
`.llm/memory/25_번호_규칙.md` 가 정본이고, 진입점 3종과 `<SOURCE_DIR>/README.md` ·
`reference/README.md` · `<LLM_ID>/README.md` · `30_산출물_및_버전_규칙.md` 가 같은 규칙을
자기 자리에서 반복한다.

```
<번호>. <제목>
 └ 두 자리   └ 점 + 공백 뒤에 제목
```

## 왜 바꿨나

### 번호는 제목이 바뀌어도 변하지 않는 손잡이다

번호 없이 제목만으로 부르면 사용자와 LLM 이 매번 전체 제목을 말해야 한다. 제목이 조금이라도
바뀌면 과거 기록과 이어지지 않는다. "03 자료" 라고만 해도 서로 아는 상태를 만드는 것이
이 규칙의 목적이다.

### 번호가 디렉토리를 가로질러 같은 자료를 가리킨다

이것이 핵심이다. 입력·재료·스크립트·산출물이 같은 번호를 쓰면 `03` 한 마디로 넷이 한꺼번에
지목된다.

```
<SOURCE_DIR>/03. <제목>/          입력 (사용자 자료)
reference/03. <제목>/             그 자료를 위해 LLM 이 만든 재료
<LLM_ID>/03. <제목>.py            생성 스크립트
<LLM_ID>/03. <제목>_v1.0.pptx     산출물
```

v0.3 에서 입력을 두 층으로 나눈 뒤 오히려 필요해진 규칙이다 — 층이 늘어날수록 "같은 자료의
다른 층" 을 묶는 수단이 있어야 한다.

### 한 디렉토리에서 한 숫자는 한 자료만

번호를 재사용하면 과거 기록의 "03 자료" 가 다른 것을 가리키게 되어 기록 전체가 신뢰를
잃는다. 자료를 빼도 번호는 비워 둔다. 중간에 끼워 넣기 위해 뒤 번호를 밀지도 않는다 —
밀면 이미 쓴 모든 기록이 어긋난다.

### 구분자로 성격을 나눈다

| 형식 | 무엇 | 번호의 뜻 |
|---|---|---|
| `NN. 제목` (점 + 공백) | 자료 — 만들어 내보내는 것 | 그 자료의 이름표 |
| `NN_제목.md` (밑줄) | 메타 문서 — 기억·규칙·요약 | 읽는 순서 |

기억 문서가 `00_INDEX.md` · `20_자료_규칙.md` 처럼 밑줄을 쓰던 관행을 규칙으로 올린 것이다.
번호를 보는 순간 자료인지 메타 문서인지 구분된다.

### `90~99` 를 비워 두는 이유

규칙 정본·요구사항 문서가 자료 번호와 섞이지 않게 하기 위해서다. 자료가 몇 개로 늘어나도
`91_마스킹_규칙.md` 는 늘 자료가 아닌 것으로 읽힌다. `00` 은 그 디렉토리 전체를 가리키는
것(색인·전체 요약)에 쓴다.

## 번호에 넣지 않은 것 — 의미와 문서 내부

두 가지를 명시적으로 금지했다.

1. **번호에 의미를 담지 않는다.** 순서·중요도·등급·난이도를 뜻하지 않는다. 자료 04 가
   자료 01 보다 나중이거나 중요하다는 뜻이 아니다. 의미를 담기 시작하면 자료를 더할 때마다
   번호를 다시 매기고 싶어지고, 그러면 손잡이가 흔들린다.
2. **번호는 문서 내부에 들어가지 않는다.** 표지·본문·마무리 어디에도 `03` 을 쓰지 않고,
   다른 자료를 번호로 참조하지 않는다. 각 자료는 독립 문서이고, 산출물을 받아 보는 사람은
   번호를 모른 채 읽어도 아무 문제가 없어야 한다. 번호는 **파일 이름과 대화에서만** 산다.

## 이전 버전에서 올 때

파일 이름 규칙만 바뀌었으므로 기존 산출물을 다시 만들 필요는 없다. 이름 앞에 번호를 붙이고
`.llm/memory/25_번호_규칙.md` 를 가져오면 된다. 이미 번호를 쓰고 있었다면 확인할 것은
하나다 — **한 디렉토리에서 같은 번호를 두 자료가 쓰고 있지 않은지.**
