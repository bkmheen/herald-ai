# 번호 규칙 — 한 숫자가 한 자료를 가리킨다

자료마다 두 자리 번호를 붙인다. **대화에서 "03 자료" 라고만 해도 무엇을 말하는지
서로 아는 것**이 목적이다.

```
<번호>. <제목>
 └ 두 자리   └ 점 + 공백 뒤에 제목
```

예 — `01. 업비트 원화 입금` · `04. 알파포유 연동`

## 번호는 디렉토리를 가로질러 같은 자료를 가리킨다

이것이 이 규칙의 핵심이다.

```
{{SOURCE_DIR}}/01. 업비트 원화 입금/          ← 자료 01 의 입력 (사용자 자료)
reference/01. 업비트 화면 캡처 목록.md         ← 자료 01 을 위해 LLM 이 만든 자료
{{LLM_ID}}/01. 업비트 원화 입금.py             ← 자료 01 의 생성 스크립트
{{LLM_ID}}/01. 업비트 원화 입금_v1.0.pptx      ← 자료 01 의 산출물
```

`01` 이라고 말하면 **입력·재료·스크립트·산출물이 한꺼번에 지목된다.** 그래서 사용자가
"01 을 고쳐라" 라고만 해도 어디를 열어야 하는지 찾을 필요가 없다.

## 한 디렉토리에서 하나의 숫자는 하나의 자료만 쓴다

- 같은 디렉토리 안에서 **번호를 겹쳐 쓰지 않는다.** `03. A` 와 `03. B` 를 함께 두지 않는다.
- **번호를 재사용하지 않는다.** 자료를 빼도 그 번호는 비워 둔다. 재활용하면 과거 기록의
  "03 자료" 가 다른 것을 가리키게 되어 기록 전체가 신뢰를 잃는다.
- 자료를 더할 때는 **다음 번호**를 쓴다. 중간에 끼워 넣기 위해 뒤 번호를 밀지 않는다
  (밀면 이미 쓴 모든 기록이 어긋난다).

## 특별 코드 — `00` 과 `90~99`

| 번호 | 무엇 | 예 |
|---|---|---|
| `00` | 그 디렉토리 **전체**를 가리키는 것 — 색인 · 전체 요약 | `00. 전체 작업 요약.md` |
| `01`~`89` | **자료** — 작업 대상 하나 | `01. 업비트 원화 입금` |
| `90`~`99` | **자료가 아닌 것** — 규칙 정본 · 요구사항 · 메타 문서 | `91_마스킹_규칙.md` |

`90~99` 를 비워 두는 이유는 하나다 — 자료가 몇 개로 늘어나도 **규칙 문서가 자료 번호와
섞이지 않는다.** 자료가 89개를 넘길 일은 없고, 넘긴다면 그때는 디렉토리를 나눌 때다.

## 구분자가 성격을 나눈다

| 형식 | 무엇 | 번호의 뜻 |
|---|---|---|
| `NN. 제목` (점 + 공백) | **자료** — 만들어 내보내는 것 | 그 자료의 이름표 |
| `NN_제목.md` (밑줄) | **메타 문서** — 기억 · 규칙 · 요약 | 읽는 순서 |

`.llm/memory/00_INDEX.md` · `20_자료_규칙.md` 처럼 기억 문서가 밑줄을 쓰는 것이 그래서다.
번호를 보는 순간 자료인지 메타 문서인지 구분된다.

## ⛔ 번호는 의미가 없고, 문서 안에 들어가지 않는다

- **번호에 의미를 담지 않는다.** 순서·중요도·등급·난이도를 뜻하지 않는다. 가리키기 위한
  **이름표**일 뿐이다. 자료 04 가 자료 01 보다 나중이거나 중요하다는 뜻이 아니다.
- **번호는 문서 내부에 들어가지 않는다.** 표지·본문·마무리 어디에도 `01` 을 쓰지 않는다.
  제목도 번호 없이 쓴다. 파일명의 번호는 **파일을 가리키기 위한 것**이지 내용의 일부가 아니다.
- **다른 자료를 번호로 참조하지 않는다.** "02 자료를 먼저 보십시오" 같은 문장을 넣지 않는다.
  **각 자료는 독립 문서다** — 자료 간 연결은 별도 문서의 몫이다.

번호는 **파일 이름과 대화에서만** 산다. 산출물을 받아 보는 사람은 번호를 모른 채 읽어도
아무 문제가 없어야 한다.

## 왜 이렇게 하나

번호 없이 제목만으로 부르면 사용자와 LLM 이 매번 전체 제목을 말해야 하고, 제목이 조금
바뀌면 과거 기록과 이어지지 않는다. 번호는 **제목이 바뀌어도 변하지 않는 손잡이**다.
그래서 번호에 의미를 담지 않고 재사용하지 않는 것이 규칙의 전부다 — 손잡이가 흔들리면
손잡이가 아니다.
