`{{SOURCE_DIR}}/` 와 짝을 이루는 **또 하나의 입력 자료 층**이다. 차이는 **누가 주인인가** 다.

| | 주인 | 쓰기 | 예 |
|---|---|---|---|
| `{{SOURCE_DIR}}/` | **사용자** | ⛔ LLM 은 읽기만 | 사용자가 넣어 준 스크린샷 · PDF |
| `reference/` | **LLM** | ○ (기록을 남기는 조건) | PDF 에서 뽑은 페이지 이미지 · 조사해 정리한 자료 · 변환한 중간 자료 |

## LLM 이 스스로 관리할 수 있다 — 단, 기록이 조건이다

만들고 고치고 지울 수 있다. 대신 **아래 대장에 한 줄을 남긴다.**
기록하지 않은 자료는 다음 세션(또는 다른 LLM)이 출처를 알 수 없어 신뢰할 수 없게 된다.

기록할 것 — **무엇을 · 언제 · 누가 · 왜 · 어디서 왔는지.**

|---|---|---|---|---|---|

## 두는 법

```
reference/
├── README.md            이 파일 — 대장
└── <번호>. <주제>/        번호는 그 자료의 번호를 그대로 쓴다
    ├── <자료 파일>
    └── <자료 파일>.md    출처·생성 방법·주의 (분량이 있는 자료는 개별 기록)
```

- **어느 자료를 위한 것인지 번호를 앞에 붙인다** — `03. 브릿지 화면 캡처/`. 특정 자료에
  묶이지 않는 공용 재료는 `90. ` 이상의 특별 코드를 쓴다 (`.llm/memory/25_번호_규칙.md`).
- 주제별 폴더로 나눈다. 자료가 하나뿐이면 폴더 없이 두어도 된다.
- 분량이 있거나 판단이 섞인 자료는 **같은 이름의 `.md`** 로 출처와 방법을 남긴다.
- **모든 LLM 이 읽는다.** 자기만 쓰는 중간 산출물은 여기가 아니라 자기 작업공간에 둔다.

## 하지 않는 것

- ⛔ **사용자 자료를 여기로 옮기지 않는다.** 가공한 결과를 두는 것은 되지만, 그때도
  대장에 원본이 무엇인지 적는다. 원본은 `{{SOURCE_DIR}}/` 에 그대로 남긴다.
- ⛔ **자기 작업공간의 산출물을 여기 두지 않는다.** 여기는 **입력**이고 작업공간은 **출력**이다.
- 사용자가 이 디렉토리에 직접 자료를 넣었다면 **그것은 사용자 자료다.** 대장에
  "사용자 제공" 으로 적고 그 항목은 읽기만 한다.
