# ha-we-ppt_gen v0.6

- 일자: 2026-09-29
- 이전: v0.5

## 무엇이 바뀌었나

**산출물을 "동명 네 파일" 로 규정했다.** 확장자만 다르고 번호·제목·버전이 완전히 같은
네 개를 한 벌로 본다.

```
<번호>. <제목>_v1.0.pptx     산출물 본체          (필수)
<번호>. <제목>_v1.0.pdf      ★ 항상 함께 만든다    (필수 — 선택이 아니다)
<번호>. <제목>_v1.0.md       슬라이드 내용 원본     (필수)
<번호>. <제목>_v1.0.py       생성 스크립트         (코드로 만들면 필수)
```

- `.llm/memory/30_산출물_및_버전_규칙.md` 를 전면 개정 — 동명 4종 원칙 · 파일별 존재 이유 ·
  **pdf 변환 명령**(`soffice --headless --convert-to pdf`) · 변환 검증(페이지 수 = 슬라이드 수) ·
  `__history__/` 로 옮길 때도 **네 파일을 함께** 옮긴다 · 사용자가 pptx 만 고쳐 온 경우의 복구 절차
- 진입점 **3종 모두**에 「산출물 규칙」 절을 두었다. v0.5 까지 `GEMINI.md` · `AGENTS.md` 에는
  이 절이 아예 없어 도구를 바꾸면 규칙이 보이지 않았다
- 생성 스크립트 이름에 **버전을 붙였다** (`03. <제목>.py` → `03. <제목>_v1.0.py`).
  버전이 없으면 산출물과 스크립트의 짝이 어긋난다
- `{{LLM_ID}}/README.md` 의 구조도와 `25_번호_규칙.md` 예시를 네 파일 기준으로 맞췄다
- `manifest.json` 의 `deliverable` 에 `pairs_with`(필수 여부 명시)와 `pdf_command` 를 넣었다

## 왜 바꿨나

**pdf 가 "또는" 이었다.** v0.5 의 규칙은 *"같은 버전의 소스나 요약을 동명 파일로 함께 둔다
(md 또는 .pdf · 생성 스크립트)"* 였다. 셋 중 하나만 있어도 규칙을 지킨 것이 되므로, 실제로는
**가장 만들기 쉬운 것 하나만 남는다.** 그런데 세 파일은 서로를 대체하지 못한다.

| 파일 | 대체 불가능한 역할 |
|---|---|
| `.pdf` | pptx 는 서체·버전·환경에 따라 다르게 열린다. pdf 는 **그때 실제로 무엇이 나왔는지의 증거**이고, 받는 사람이 도구 없이 볼 수 있는 유일한 형식이다 |
| `.md` | pptx 는 열어야 내용을 안다. **검색·diff·인계**가 되는 것은 md 뿐이다 |
| `.py` | 없으면 다음 버전을 **처음부터 다시** 만든다 |

**스크립트에 버전이 없던 문제.** `03. <제목>.py` 하나가 `_v0.1` ~ `_v1.0` 산출물 전체를
가리키게 되어, 어느 산출물을 만든 코드인지 알 수 없었다. 산출물이 `__history__/` 로 내려갈 때
스크립트는 따라갈 수도 없었다. 이름에 버전을 넣으면 **네 파일이 한 덩어리로 움직인다.**

**진입점 3종 동기화.** v0.5 에서 `GEMINI.md` · `AGENTS.md` 는 산출물 규칙을 `CLAUDE.md` 에
맡기고 아무것도 적지 않았다. 이 디렉토리는 여러 LLM 이 오가는 것을 전제하므로, 도구를 바꿨을 때
보이는 규칙이 달라지면 그 전제가 깨진다. v0.5 가 진행기록 절을 3종에 모두 넣은 것과 같은 이유다.

**"조용히 건너뛰지 않는다" 를 명문화했다.** 변환 도구가 없는 컴퓨터에서 pdf 를 만들지 못하는
일은 실제로 생긴다. 그때 pptx 만 놓고 "완료" 라고 보고하면 사용자는 pdf 가 있다고 믿는다.
규칙에 **보고 의무**를 넣었다.

## 이관 시 주의

v0.5 이하로 만든 디렉토리에 v0.6 을 다시 뿌려도 **기존 파일은 덮지 않는다**(멱등).
따라서 이미 만든 디렉토리에서는 아래 여섯 파일의 해당 절을 **손으로 옮겨야** 한다.

- `CLAUDE.md` · `GEMINI.md` · `AGENTS.md` 의 「산출물 규칙」 절
- `.llm/memory/30_산출물_및_버전_규칙.md` (전면 개정본)
- `.llm/memory/25_번호_규칙.md` 의 예시
- `<llm>/README.md` 의 구조도

이미 만들어 둔 산출물에 pdf·md·py 가 빠져 있으면 **그 버전에 맞춰 만들어 채운다.**
내용이 달라지면 버전을 올린다 (소급해 같은 버전으로 덮지 않는다).
