# 날짜별 진행기록 작성법

> **사용자가 요청하면 즉시 쓸 수 있어야 한다.** 어디에 · 무엇을 모아 · 어떤 형식으로 쓰는지가
> 정해져 있지 않으면 요청받을 때마다 다른 모양이 나오고, 다음 LLM 이 이어 쓰지 못한다.

## 언제 쓰나

사용자가 아래처럼 말하면 **`.llm/PROGRESS.md` 를 갱신하는 작업**이다.

- "진행기록" · "날짜별 진행기록" · "진행기록 써 줘 / 갱신해 줘"
- "진행상황 정리해 줘" · "지금까지 뭐 했는지 날짜별로"
- "어디까지 왔는지 정리"

> 사용자가 **기간을 한정**하면 (예: "9월치만", "어제 것만") 그 범위만 쓰고,
> 파일의 나머지 부분은 건드리지 않는다.

## 어디에 쓰나

**`.llm/PROGRESS.md` 한 파일.** 공용이므로 모든 LLM 이 같은 파일에 쓴다.
새 파일을 만들거나 자기 작업공간에 따로 두지 않는다 — 그러면 프로젝트의 이력이 쪼개진다.

## `BOARD.md` 와 무엇이 다른가 — 이것을 혼동하면 두 파일이 다 낡는다

| | `BOARD.md` | `PROGRESS.md` |
|---|---|---|
| 답하는 질문 | **지금 어디인가** | **어떻게 여기까지 왔는가** |
| 시간 | 현재 한 시점 | 날짜순 누적 |
| 갱신 방식 | 덮어쓴다 (낡은 줄은 지운다) | **덧붙인다** (지난 항목은 고치지 않는다) |
| 갱신 시점 | 작업을 마칠 때마다 | 사용자가 요청할 때 |
| 담는 것 | 최신 산출물 · 다음 할 일 · 막힌 곳 | 그날 한 일 · 그날 내린 결정 · 그날 본 문제 |

⛔ **같은 숫자를 양쪽에 적지 않는다.** "현재 v0.3" 은 `BOARD.md` 만, "9/29 에 v0.3 을 냈다" 는
`PROGRESS.md` 만. 양쪽에 적으면 반드시 한쪽이 낡는다.

## 무엇을 모아서 쓰나 — 이 순서로 읽는다

1. **`.llm/sessions/`** · **`.llm/agents/<llm>/sessions/`** — 파일명의 날짜가 1차 근거다
2. **`.llm/BOARD.md` 의 「결정 이력」** — 날짜와 결정이 이미 표로 있다
3. **`<llm>/__history__/*_CHANGE.md`** — 산출물이 언제 어떻게 바뀌었나
4. **`<llm>/STATUS.md`** — 각 LLM 이 스스로 적은 진행
5. `CHANGELOG.md` · `DEVLOG.md` (커밋 규약을 쓰는 디렉토리면) — 커밋 단위 이력
6. 위로 채워지지 않는 날은 **파일 수정시각**(`ls -lT`)을 참고하되 **추정임을 밝힌다**

## 형식

**최신 날짜가 위로.** 파일 맨 위가 가장 최근이다.

```markdown
## YYYY-MM-DD (요일)

**한 줄** — 그날을 한 문장으로.

| 작업자 | 한 일 |
|---|---|
| <llm> | … |
| 사용자 | … |

- **결정**: (그날 정해진 것. 없으면 줄 자체를 쓰지 않는다)
- **막힌 것**: (그날 드러난 문제. 없으면 생략)
- **근거**: `sessions/YYYY-MM-DD_<도구>_<주제>.md`
```

- **작업자에 사용자도 적는다.** 사용자가 직접 원본을 고친 날도 진행이다.
- **근거를 반드시 단다.** 근거를 댈 수 없는 항목은 쓰지 않는다.
- 하루에 여러 LLM 이 일했으면 **한 날짜 아래 작업자별로** 나눈다. 날짜를 쪼개지 않는다.

## 지켜야 할 것

- ⛔ **날짜를 지어내지 않는다.** 근거가 없으면 `날짜 미상` 으로 묶고 왜 미상인지 적는다.
- ⛔ **지난 항목을 고쳐 쓰지 않는다.** 사실이 틀렸던 것으로 드러나면 **그날 항목은 두고**
  오늘 항목에 "N월 N일의 X 는 사실이 아니었다" 로 적는다. 이력을 덮으면 이력이 아니다.
- ⛔ **원 문자 금지** — `①②③`, `⑴`, `ⓐ` 등을 쓰지 않는다. `(1) (2) (3)` 으로 쓴다.
- **하지 않은 일을 적지 않는다.** "검토했다" 와 "읽었다" 를 구별한다.
- 한 날짜 항목은 **화면 한 눈에 들어오는 분량**으로. 자세한 것은 `.llm/sessions/` 가 맡는다.

## 작성한 뒤

1. `.llm/BOARD.md` 의 한 줄 요약이 `PROGRESS.md` 의 맨 위 항목과 **어긋나지 않는지** 본다.
2. 어긋나면 **`BOARD.md` 쪽을 고친다** (현재 상태의 단일 출처는 `BOARD.md` 다).
3. 사용자에게 **갱신한 날짜 범위와 항목 수**를 보고한다.
