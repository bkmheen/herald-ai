# ha-we-ppt_gen v0.7

- 일자: 2026-09-30
- 이전: v0.6

## 무엇이 바뀌었나

**모든 pptx 가 갖춰야 할 공통 골격을 규정했다.** v0.6 이 "한 산출물 = 동명 네 파일" 이라는
**파일 규칙**을 세웠다면, v0.7 은 **문서 안쪽의 골격**을 세운다.

```
표지      제목 · 부제 · 버전 v0.0 · 발행일 · 저자 · 소속 · 생성형 AI 사용 고지
2쪽       「개정 이력」 (버전 · 일자 · 핵심 변경)
머리말    왼쪽 제목            오른쪽 v버전 · 발행일
꼬리말    왼쪽 저자 · 소속      오른쪽 n / N
출처 앞   「AI 사용 내역」 (모델 · 맡은 일 · 시점)
```

- `.llm/memory/30_산출물_및_버전_규칙.md` 에 **「표지·머리말·꼬리말·개정 이력」** 절과
  **「저자와 AI 사용 표기」** 절을 넣었다
- 진입점 **3종 모두**(`CLAUDE.md`·`GEMINI.md`·`AGENTS.md`)에 같은 요약을 넣었다
- `manifest.json` 의 `deliverable` 에 **`layout`** 을 두어 `ha-we show` 에서 보이게 했다
- ⛔ **저자·소속은 사용자에게 한 번 묻고 고정**한다. 추측하지 않는다

## 왜 바꿨나

**출력물 한 장은 스스로를 설명하지 못했다.** 같은 제목의 pptx 가 v0.1~v0.5 로 늘어나면,
회의에서 한 장을 뽑거나 pdf 를 부분 공유했을 때 **어느 버전인지·몇 쪽짜리인지·누가 만든
것인지** 알 수 없다. 파일 이름에 버전이 있어도 **인쇄하는 순간 사라진다.**

그래서 세 자리에 나눠 담았다.

| 자리 | 답하는 질문 |
|---|---|
| **표지의 버전** | 이 묶음은 어느 버전인가 |
| **2쪽 개정 이력** | 직전 버전에서 무엇이 달라졌나 |
| **머리말·꼬리말** | 이 **한 장**은 어느 자료의 몇 번째 쪽이고 누가 만들었나 |

**쪽수를 `n / N` 으로 적은 이유.** 전체 쪽수가 함께 보이면 **빠진 장이 있는지 즉시 드러난다.**
`12` 만 적으면 그 판단이 안 된다.

**개정 이력을 자료 안에 넣은 이유.** `__history__/` 의 `_CHANGE.md` 는 상세하지만
**자료 밖에 있다.** 받는 사람은 그것을 보지 못한다. 2쪽에 세 칸짜리 표를 두면 읽기 전에
무엇이 달라졌는지 알 수 있고, 상세 사유는 여전히 `_CHANGE.md` 가 맡는다.

**LLM 중립으로 쓴 이유.** 이 디렉토리는 여러 LLM 이 오가는 것을 전제한다. 골격이 모델마다
다르면 같은 프로젝트의 자료가 제각각이 된다. 그래서 규칙 문장을 특정 모델에 매이지 않게 쓰고,
**다른 점은 「AI 사용 내역」의 모델 이름뿐**이 되도록 했다.

**「AI 사용 내역」을 둔 이유.** 표지 한 줄로는 "무엇을 맡겼는지" 가 드러나지 않는다.
모델·맡은 일·시점을 표로 적고 검증 원칙을 함께 실어 자료의 신뢰 근거를 남긴다.
그리고 ⛔ **AI 를 저자로 적지 않는다** — 저자는 사람이고 AI 는 사용한 도구다.
특허 청구항·명세서에는 **AI 를 발명자로 적지 않는다**(주요국 특허청이 인정하지 않는다).

## 이관 시 주의

v0.6 이하로 만든 디렉토리에 v0.7 을 다시 뿌려도 **기존 파일은 덮지 않는다**(멱등).
아래 네 파일의 해당 절을 **손으로 옮겨야** 한다.

- `.llm/memory/30_산출물_및_버전_규칙.md` (「표지·머리말·꼬리말·개정 이력」 + 「저자와 AI 사용 표기」)
- `CLAUDE.md` · `GEMINI.md` · `AGENTS.md` 의 산출물 규칙 절

이미 만들어 둔 pptx 에 머리말·꼬리말이 없으면, **다음 버전을 올릴 때 함께 넣는다.**
소급해 같은 버전으로 덮지 않는다.
