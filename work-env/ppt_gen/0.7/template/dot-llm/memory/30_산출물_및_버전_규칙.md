# 산출물 및 버전 규칙

## 한 산출물은 **이름이 같은 파일 네 개**다

⛔ **확장자만 다르고 이름은 완전히 같아야 한다** — 번호·제목·버전까지 전부.

```
<llm>/<번호>. <제목>_v1.0.pptx     산출물 본체
<llm>/<번호>. <제목>_v1.0.pdf      ★ 항상 함께 만든다 (선택 아님)
<llm>/<번호>. <제목>_v1.0.md       슬라이드 내용의 원본 (열지 않고 읽는다·diff 한다)
<llm>/<번호>. <제목>_v1.0.py       생성 스크립트 (코드로 만드는 경우)
```

예 — `claude/03. 메타마스크로 자금 이체_v1.0.{pptx,pdf,md,py}`

| 파일 | 왜 필요한가 | 필수 여부 |
|---|---|---|
| `.pptx` | 편집 가능한 산출물 | **필수** |
| `.pdf` | pptx 는 서체·버전·환경에 따라 다르게 열린다. **그때 실제로 무엇이 나왔는지의 증거**이며, 받는 사람이 도구 없이 볼 수 있다 | **필수** — pptx 를 만들면 예외 없이 함께 만든다 |
| `.md` | pptx 는 열어야 내용을 안다. md 가 있으면 검색·diff·인계가 된다 | **필수** |
| `.py` | 재생성 가능성. 스크립트가 없으면 다음 버전은 처음부터 다시 만든다 | 코드로 만들면 **필수** |

- ⛔ **pdf 가 없는 상태를 "완료" 라고 보고하지 않는다.**
- ⛔ 넷 중 하나만 고치고 나머지를 두지 않는다. **네 파일은 항상 같은 버전·같은 내용**이다.
- 생성에 다른 재료가 필요하면(설정·데이터) 같은 이름에 확장자만 달리해 옆에 둔다
  (예: `_v1.0.json`). 이름이 다르면 다음 세션이 짝을 찾지 못한다.

## 파일명

**앞에 자료 번호, 끝에 버전**을 붙인다.

- 번호는 그 자료의 번호를 그대로 쓴다. 입력·재료·스크립트·산출물이 같은 번호를 공유한다
  ([`25_번호_규칙.md`](25_번호_규칙.md)).
- 시작은 `v0.1`. 구조·내용의 큰 변화 시 앞자리를 올린다 (`v1.0`).
- **작업공간에는 최종 버전 한 벌(네 파일)만 둔다.**
- ⛔ 번호와 버전은 **파일 이름에만** 산다. 문서 표지·본문에는 넣지 않는다.

## pdf 는 이렇게 만든다

```bash
soffice --headless --convert-to pdf --outdir "<출력 디렉토리>" "<번호>. <제목>_v1.0.pptx"
```

- macOS 에서 `soffice` 가 PATH 에 없으면
  `/Applications/LibreOffice.app/Contents/MacOS/soffice` 를 쓴다.
- 변환 뒤 **pdf 페이지 수가 슬라이드 수와 같은지 확인**한다. 다르면 변환이 깨진 것이다.
- 변환 도구가 없는 컴퓨터라면 **그 사실을 사용자에게 보고**한다. 조용히 건너뛰지 않는다.
- 서체가 없어 글자가 바뀌는 일이 잦다. pdf 를 눈으로 한 장이라도 확인한다.

## 이전 버전은 `__history__/` 로 — **네 파일을 함께 옮긴다**

```
<llm>/__history__/<번호>. <제목>_v0.9.pptx
<llm>/__history__/<번호>. <제목>_v0.9.pdf
<llm>/__history__/<번호>. <제목>_v0.9.md
<llm>/__history__/<번호>. <제목>_v0.9.py
<llm>/__history__/<번호>. <제목>_v1.0_CHANGE.md   ← v0.9 대비 무엇이 왜 바뀌었나
```

`_CHANGE.md` 에 적을 것 — 날짜 · 직전 버전 · 한 줄 요약 · 변경 항목.
**무엇이 바뀌었나** 만 적지 말고 **왜 바꿨나**를 함께 적는다.

## 사용자가 직접 수정한 버전

사용자가 pptx 를 직접 고쳤으면 버전코드 뒤에 소문자를 붙인다 (`_v0.1a`).
그 파일을 읽어 **직전 버전과의 차이를 파악**하고 기록한 뒤 의견을 주고받는다.
반영한 다음 버전은 기본 코드를 올린다 (`v0.1a` → `v0.2`).
이때 사용자가 준 것은 pptx 하나뿐이므로, **나머지 세 파일을 그 내용에 맞춰 다시 만든다.**

## 표지·머리말·꼬리말·개정 이력 — 모든 pptx 의 공통 골격

> ⚠️ **어느 LLM 이 만들든 똑같이 적용된다.** 작업공간이 달라도 골격은 같다.
> 다른 점은 「AI 사용 내역」에 적히는 모델 이름뿐이다.

### (1) 표지

```
<제목>
<부제>

버전 v<버전>  ·  <발행일 YYYY-MM-DD>

<저자>  ·  <소속>                              ← 크게·진하게
<발행일>
자료 조사 · 정리에 생성형 AI 사용 (<실제 쓴 모델>)
<그 자료의 표기 원칙 한 줄>
```

**버전을 파일 이름에만 두지 않는다.** 인쇄하거나 화면에 띄우면 파일 이름이 사라진다.

### (2) 2쪽 — 「개정 이력」

| 버전 | 일자 | 핵심 변경 |
|---|---|---|
| v0.1 | YYYY-MM-DD | 최초 작성 (N장) |
| **v0.2** | YYYY-MM-DD | (이번 버전은 굵게) |

받는 사람은 `__history__/` 의 `_CHANGE.md` 를 보지 못한다. **자료 안에서** 무엇이 달라졌는지
알 수 있어야 한다. 상세 사유는 그대로 `_CHANGE.md` 가 맡고, 이 표는 **한 줄 요약**만 적는다.

### (3) 머리말·꼬리말 — 표지를 뺀 모든 슬라이드

```
머리말  왼쪽 : <자료 제목>              오른쪽 : v<버전>  ·  <발행일>
────────────────────────────────────────────────────────────────
                          (본문)
────────────────────────────────────────────────────────────────
꼬리말  왼쪽 : <저자>  ·  <소속>         오른쪽 : <현재 쪽> / <전체 쪽>
```

- 쪽수는 **`n / N`** — 빠진 장이 있는지 즉시 보인다
- 9 pt 회색, 쪽수만 진하게. 본문과 섞이지 않게 얇은 구분선을 둔다
- 출처 캡션은 꼬리말 **위**에 둔다 (겹치지 않게)

### (4) 저자·소속은 한 번만 묻고 고정한다

처음 만들 때 사용자에게 **저자 표기와 소속**을 묻고, 이후 모든 자료에 같은 값을 쓴다.
⛔ **추측하지 않는다.**

## 저자와 AI 사용 표기

산출물 **출처 슬라이드 앞**에 「AI 사용 내역」 한 장을 둔다.

| 모델 | 맡은 일 | 시점 |
|---|---|---|
| <모델명·버전> (<제공사>) | 자료 조사 · 계산 · 초안 작성 | YYYY-MM-DD ~ |

### 규칙

- ⛔ **실제로 쓴 모델만 적는다.** 앞으로 쓸 예정인 모델을 미리 적지 않는다
- 모델이 늘면 **줄을 더한다**. 표지 괄호도 함께 늘린다
- **모델명은 버전까지** 적는다 ("Claude" 가 아니라 "Claude Opus 5")
- 「AI 사용 내역」에는 **검증 원칙**을 함께 적는다 — 문제 제기·가설·오류 지적·감수는 사람이
  했다는 것, AI 산출 수치를 1차 출처로 확인했다는 것, 확인하지 못한 것은 "추정" 으로
  표시했다는 것
- ⛔ **AI 를 저자로 적지 않는다.** 저자는 사람이고 AI 는 **사용한 도구**로 고지한다.
  특허 청구항·명세서에는 **AI 를 발명자로 적지 않는다** (주요국 특허청이 인정하지 않는다)

### 여러 LLM 이 각자 자료를 만들 때

작업공간마다 주 사용 모델이 다르다. **표기 형식은 같게** 쓰고 괄호와 표만 그 자료가 실제로
쓴 것으로 채운다. 다른 LLM 의 자료를 이어받아 고쳤다면 **두 모델을 모두 적고 맡은 일을 구분**한다.

## 조사 결과를 인용한 산출물

조사 결과(`reference/`)를 인용했으면 **md 는 문서 끝 출처 표**, **pptx 는 슬라이드 하단
출처 캡션**(이미지는 이미지 아래)을 반드시 넣는다. 출처는 **발행처·제목·일자**로 쓰고
⛔ 자료 번호로 참조하지 않는다. 조사가 갱신되면 그 조사를 인용한 산출물도 함께 올린다.

## 생성이 코드로 이루어지는 경우

- 버전 상수를 스크립트 안에 두고, 올려서 빌드하면 이전 버전 **네 파일이 자동으로
  `__history__/` 로** 옮겨지게 하는 것을 권한다. 사람이 손으로 옮기면 빠뜨린다.
- **빌드 스크립트가 pdf 변환까지 수행**하게 한다. 사람이 따로 하면 잊는다.
- `_CHANGE.md` 는 자동 생성할 수 없으므로 빌드 로그가 작성을 상기시키게 한다.
