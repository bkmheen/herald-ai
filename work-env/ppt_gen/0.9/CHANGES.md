# ha-we-ppt_gen v0.9

- 일자: 2026-09-30
- 이전: v0.8

## 무엇이 바뀌었나

**규칙을 실행 가능한 템플릿으로 만들었다.** v0.6~v0.8 이 글로 정한 것을
`.llm/templates/template_2609/` 한 벌이 **자동으로 수행**한다.

```
.llm/templates/template_2609/
├── template_2609.py    md 를 읽어 pptx·pdf 를 만드는 생성기
├── template_2609.md    골격이 들어 있는 빈 자료 (복사해서 쓴다)
└── README.md           사용법 · md 문법 · 환경 의존 · 유래
```

쓰는 법은 세 줄이다.

```bash
cp .llm/templates/template_2609/template_2609.py  "<번호>. <제목>_v0.1.py"
cp .llm/templates/template_2609/template_2609.md  "<번호>. <제목>_v0.1.md"
python3 "<번호>. <제목>_v0.1.py"
```

`.py` 에서 고치는 것은 **상수 여섯 줄**(`NUMBER`·`TITLE`·`VERSION`·`DATE`·`AUTHOR`·`AFFIL`)뿐이다.

### 스크립트가 자동으로 하는 것

| 자리 | 내용 |
|---|---|
| 표지 | 제목 42 · 부제 21 · `버전 v0.0 · 발행일` 15 · **저자·소속 21** · AI 고지 14 · 표기 원칙 12 pt |
| 2쪽 | 「개정 이력」 |
| 머리말·꼬리말 | `제목 \| v버전·일자` / `저자·소속 \| n / N` |
| 산출 | `.pptx` + **`.pdf`**(필수), 페이지 수 = 슬라이드 수 검증 |
| 이력 | 이전 버전 **네 파일**을 `__history__/` 로 이동 |

### 규칙 문서·진입점

- `30_산출물_및_버전_규칙.md` 에 **「기본 템플릿 — template_2609」** 절 신설:
  ⛔ **특별한 지정이 없으면 이 템플릿으로 만든다**
- 진입점 **3종 모두**와 `memory/00_INDEX.md` 에 같은 안내를 넣었다
- ⛔ **저자·소속은 사용자에게 묻고 고정**한다. 템플릿의 `<저자>`·`<소속>` 을 그대로 두지 않는다
- `manifest.json` 에 `deliverable.default_template` 과 `creates` 3개 항목을 추가했다

## 왜 바꿨나

**글로 쓴 규칙은 구현자마다 다르게 해석된다.** v0.8 의 DEVLOG 에 적었듯, "무엇을 적을지" 만
정하면 크기·위치가 제각각이 된다. 그래서 크기까지 명시했는데, **그래도 매번 생성기를 새로
작성해야 한다면** 미묘한 차이는 계속 생긴다.

실제로 한 프로젝트 안에서도 먼저 만든 자료의 생성기에는 코드펜스 렌더링이 없고 나중 것에는
있는 일이 벌어졌다. **규칙을 지키는 가장 확실한 방법은 규칙을 실행하는 코드를 함께 주는 것**이다.

**템플릿을 `.llm/` 에 둔 이유.** `<llm>/` 작업공간이 아니라 **공용 영역**에 둔다.
여러 LLM 이 같은 템플릿을 복사해 쓰므로, 작업공간마다 사본이 갈라지면 안 된다.

**이름의 `2609`.** 이 서식이 정리된 시점(2026년 9월)이다. 서식이 크게 바뀌면 새 이름을 붙이고
옛 템플릿은 남겨 둔다 — 이미 그 서식으로 만든 자료를 다시 만들 수 있어야 한다.

## 유래

손으로 옮겨야 한다.
