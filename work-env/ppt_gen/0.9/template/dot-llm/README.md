# `.llm/` — LLM 기억·기록 저장소

이 프로젝트에서 일하는 **모든 LLM 세션의 기억과 작업 기록은 이 디렉토리 안에만** 둔다.
도구의 홈 디렉토리(`~/.claude`, `~/.gemini` 등)에는 남기지 않는다.
그래야 이 디렉토리를 **어느 컴퓨터의 어느 위치로 옮겨도** 같은 기억으로 이어서 일할 수 있다.

## 구조

```
.llm/
├── README.md              이 파일
├── BOARD.md               ★ 진행 현황판 — 지금 어디인가
├── PROGRESS.md            ★ 날짜별 진행기록 — 어떻게 여기까지 왔는가
├── memory/                공용 기억 (모든 LLM 이 읽고 쓴다)
│   ├── 00_INDEX.md
│   ├── 01_프로젝트_개요.md
│   ├── 10_사용자_작업_방식.md
│   ├── 20_자료_규칙.md
│   ├── 30_산출물_및_버전_규칙.md
│   ├── 40_LLM_협업_규칙.md
│   ├── 45_진행기록_작성법.md
│   └── 50_이관_작업절차.md
├── sessions/              공용 세션 기록 (다른 LLM 도 읽어야 하는 것)
└── agents/                LLM 개별 기억 — 자기 것만 쓴다
    └── <llm>/
        ├── memory/
        └── sessions/
```

## 공용과 개별을 나누는 기준

| | 공용 `.llm/memory/` | 개별 `.llm/agents/<llm>/memory/` |
|---|---|---|
| 담는 것 | 프로젝트 맥락 · 사용자 지시 · 규칙 · **판단 근거** | 그 LLM 의 구현 방식 · 겪은 함정 · 도구별 제약 |
| 쓰는 주체 | 모든 LLM | 그 LLM 만 |
| 읽는 주체 | 모든 LLM | 모든 LLM (인계를 위해) |

판단 기준 한 줄 — **"다른 LLM 이 이어받을 때 알아야 하나?"** → 예면 공용, 아니면 개별.

## 기억 파일 작성 규칙

1. **번호 접두** — 파일명 앞의 숫자가 읽는 순서다. 자리를 비워 두었으므로 새 주제는
   가운데 번호로 끼워 넣는다.

2. **프론트매터** — 파일 머리에 둔다.

```markdown
---
name: <짧은-kebab-case-슬러그>
description: <한 줄 요약 — 관련성 판단에 쓰인다>
metadata:
  type: user | feedback | project | reference
---
```

`type` — `user` 사용자가 누구인지 · `feedback` 일하는 방식 지시 ·
`project` 코드로 알 수 없는 맥락 · `reference` 외부 자료 위치.

3. ⛔ **절대경로 금지** — 이 디렉토리가 옮겨지면 깨진다. 항상 프로젝트 루트 기준 상대경로.

4. **중복 금지** — 이미 있는 파일이 다루는 내용이면 그 파일을 고친다. 틀린 기억은 지운다.

5. **코드가 이미 말하는 것은 적지 않는다** — 디렉토리 구조·함수 이름·수정 내역은 코드와
   `__history__/` 가 담고 있다. 기억에는 **코드를 읽어도 알 수 없는 것**만 남긴다.

## 세션 기록 작성 규칙

작업이 한 덩어리 끝날 때마다 남긴다.

```
.llm/sessions/YYYY-MM-DD_<도구>_<주제>.md          공용
.llm/agents/<llm>/sessions/YYYY-MM-DD_<주제>.md    개별
```

무엇을 왜 그렇게 했는지, 그리고 **하지 않기로 한 것과 그 이유**를 함께 적는다.
후자가 다음 세션(또는 다른 LLM)이 같은 길을 다시 헤매지 않게 한다.

## 두 현황 파일을 구별한다

| | `BOARD.md` | `PROGRESS.md` |
|---|---|---|
| 답하는 질문 | **지금 어디인가** | **어떻게 여기까지 왔는가** |
| 갱신 방식 | 덮어쓴다 (낡은 줄은 지운다) | 덧붙인다 (지난 항목은 고치지 않는다) |
| 언제 쓰나 | 작업을 마칠 때마다 | 사용자가 **"진행기록"** 을 요청할 때 |

⛔ **같은 숫자를 양쪽에 적지 않는다.** 작성법은 `memory/45_진행기록_작성법.md`.

## 작업을 마칠 때

`BOARD.md` 의 **내 줄을 갱신한다.** 이것을 빠뜨리면 다른 LLM 이 이어받을 수 없다.
