## 무엇을 담았나

여러 맥을 오가며 발표자료를 만드는 동안 **매번 다시 만들게 되는 것**을 한 벌로 묶었다.

| 구성 | 푸는 문제 |
|------|-----------|
| `CLAUDE.md` 세션 시작 절차 | 대화 기록이 컴퓨터 간에 동기화되지 않는다 → 이어받는 방법이 디렉토리 안에 있어야 한다 |
| `.claude/hooks/sync-memory.sh` | 홈의 기억 폴더도 동기화되지 않는다 → 사본을 프로젝트에 두고 SessionStart 에 복원 |
| `<PROGRESS_DIR>/` | 서술형 이력 — 무슨 일이 있었고 왜 그렇게 정했나 |
| `<DELIVERABLE_DIR>/` | 산출물 이력 — pptx 와 동명 md 를 쌍으로 (열지 않고도 읽기 위해) |
| `.gitignore` | `.omc/`·`.session-logs/` 등 컴퓨터별 임시 상태 제외 |

## 설계에서 고른 것

- **기억 훅의 슬러그를 경로에서 계산한다.** Claude Code 가 `~/.claude/projects/<slug>/memory/` 의
  슬러그를 프로젝트 절대경로로 만들기 때문에, 맥이나 경로가 바뀌면 기억이 끊긴다.
  훅이 같은 방식으로 슬러그를 계산하므로 **어디에 두어도 대응**한다.
- **삭제는 전파하지 않는다** (`rsync -au`, `--delete` 없음). 한쪽의 사고가 양쪽을 지우지 않게.
  대가로, 기억을 지울 때는 양쪽에서 지워야 한다.
- **pptx 와 md 를 쌍으로 강제한다.** 사용자는 pptx 를 보지만 내용 파악은 md 로 빠르게 하고 싶어 한다.
- **진행 기록은 고치지 않고 얹는다.** 결정의 순서를 되짚을 수 있어야 한다.
- 템플릿 안의 `.claude`·`.gitignore` 는 저장소에서 `dot-claude/`·`_gitignore` 로 보관한다.
  그대로 두면 herald-ai 자신의 git·Claude Code 설정에 섞인다.

## 알려진 한계

- **git 은 만들지 않는다.** `git init` 위치는 동기화 수단(iCloud/Dropbox/git)과 얽힌 판단이라
  사용자가 정해야 한다. 커밋 규약이 필요하면 `--with-convention` 으로 이어 붙인다.
- 산출물이 pptx 가 아니면 이 환경이 아니다. 다른 산출물은 별도 `ha-we-*` 로 만든다.
