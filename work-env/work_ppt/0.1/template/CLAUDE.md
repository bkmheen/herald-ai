# {{PROJECT_NAME}} — 프로젝트 작업 규칙

이 파일은 이 디렉토리에서 Claude Code 를 실행하면 **어느 컴퓨터에서든** 자동으로 읽힌다.
**대화 기록은 컴퓨터 간에 동기화되지 않으므로**, 아래 파일들이 세션 간 인계의 유일한 수단이다.

> 작업환경: `ha-we-{{WE_ID}}` v{{WE_VERSION}} (herald-ai `work-env/`)
> {{DATE}} 생성. 이 환경 자체의 개선은 herald-ai 에 반영하고 버전을 올린다.

## 세션 시작 시 반드시 할 일

1. `{{PROGRESS_DIR}}/` 에서 **순번이 가장 큰 파일**을 읽어 직전 상태와 "다음 단계" 를 파악한다.
2. `{{MEMORY_DIR}}/MEMORY.md` 와 그 안에 링크된 기억 파일을 읽는다.
   (SessionStart 훅이 이 사본을 `~/.claude/projects/<slug>/memory/` 로 복원하지만,
   훅 신뢰 확인 전에는 미동작할 수 있으므로 직접 읽는다.)
3. 사용자에게 "어디까지 진행되었는지" 한두 줄로 확인시킨 뒤 이어서 작업한다.

## 디렉토리 규칙

| 경로 | 용도 | 규칙 |
|------|------|------|
| `{{DELIVERABLE_DIR}}/` | 산출물 | `v{버전} {대표 변경사항}.pptx` + **같은 이름의 `.md`(+생성 소스)** 를 반드시 함께 저장·동기화. 사용자 수동 수정본은 `v0.1a` 식 소문자 접미사 → 직전 버전과 차이를 파악해 의견 교환. 상세: `{{DELIVERABLE_DIR}}/00. 버전 관리 규칙.md` (버전 이력 표 갱신) |
| `{{PROGRESS_DIR}}/` | 진행 기록 | 진전이 있을 때마다 `{두 자리 순번}. {제목}.md` **새 파일** 추가. 기록일·한 일·결정 사항·다음 단계 포함 |
| `{{MEMORY_DIR}}/` | Claude 기억 사본 | `.claude/hooks/sync-memory.sh` 가 홈 memory 와 양방향 동기화. 기억을 새로 저장하면 `~/.claude/projects/<slug>/memory/` 에 쓰고, 훅이 사본을 갱신 |
| `.claude/` | 훅·설정 | SessionStart(restore) / PostToolUse·Stop(backup). 수정 시 `{{PROGRESS_DIR}}/` 에 기록 |
| `.omc/` · `.session-logs/` | 로컬 세션 상태 | 무시 (컴퓨터별 임시 상태) |

### 왜 이렇게 나누나

- **`{{PROGRESS_DIR}}/` 는 서술형 이력이다** — "무슨 일이 있었고 왜 그렇게 정했나". 기존 파일을
  고치지 않고 새 순번을 얹는 것은, 나중에 결정의 순서를 되짚을 수 있게 하기 위함이다.
- **`{{DELIVERABLE_DIR}}/` 는 산출물 이력이다** — 같은 물건의 버전을 갈아 끼운다.
  pptx 와 동명 md 를 쌍으로 두는 이유는, **파일을 열지 않고도 내용을 읽기 위해서**다.
  둘의 내용이 어긋난 상태로 남기지 않는다.
- **`{{MEMORY_DIR}}/` 는 기억이다** — 훅이 슬러그를 경로에서 자동 계산하므로, 이 디렉토리를
  어느 맥의 어느 경로에 두어도 같은 기억으로 이어진다.

## 응대 원칙

- 존댓말, 정중하게. 사용자의 유급 비서로서 목적까지 고려해 응대한다.
- 결과 보고는 사실 그대로. 실패·미완은 숨기지 않는다.
- 모든 작업 시작·종료 시 task-tracker 스킬이 설치되어 있으면 사용한다 (없는 컴퓨터에서는 건너뛴다).
